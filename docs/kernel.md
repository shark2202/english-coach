# 最小理论内核

## 为什么有这个文件

english-coach 的两份设计（[org-design.md](org-design.md) / [app-design.md](app-design.md)）源自 ai-native 组织理论体系。为使本项目**可独立交付**，把设计实际用到的机制收敛为最小内核，在此自成一体地定义；两份文档中对 "ai-native 仓" 的引用仅作溯源，不是阅读前提。若本内核与源仓表述冲突，以源仓为准并回改本文件。

## 机制清单（十条）

### 1. 判断基准三问
任何重要决策不只按预期收益判断，必须同时回答：**维度**（从哪些维度判断成功）、**死法**（判断错误时系统最可能如何失败）、**可逆性**（失败后能否以有限成本回退并通过反馈收敛）。本项目用于：设计决策、技术选型、周度复盘。裁定权在学习者（见 §10）。

### 2. 可恢复性不变量族（学习域实例化，L- 系列）
- **L-TREE 任务树可重建**：学习任务树仅从账本文件即可完整重建，不依赖任何会话上下文；
- **L-NOLOSS 进度不丢失**：进度只认账本不认对话——"上次聊到哪"不算进度，未落盘=可弃；
- **L-RESUME 断点续学**：续学点 = 最后一次落盘的轮次；任何时刻中断，损失上界 = 一轮交互；
- **L-REFORM 随时重建**：组织/App 可随时解散重装，凭账本 + 设计文档完全恢复，不依赖任何个体（人或会话）的记忆或在场。
（源：可恢复性不变量族 I-TREE/I-NOLOSS/I-RESUME/I-REFORM，ai-native 仓 2026-10-01 提案）

### 3. I-DISC 判别器独立
生成者与判定者必须隔离（不同上下文，理想上不同模型/会话）。本项目：陪练官出题 ≠ 判读官判卷；离线 T0 预嵌判定的隔离在生成期完成（出题与评分细则由两个独立生成产出）。违反后果：错误被固化——学了错的语感还不自知。

### 4. 只认产物不认对话
交接与状态只认落盘产物；对话内容不构成进度或证据。本项目：每轮微落盘、会话摘要从 journal 派生、续学点来自 journal 尾行。

### 5. 状态只能由产物跃迁
状态声明必须由落盘产物支撑——"90% done"是声明不是状态。本项目：账本行的写入就是状态跃迁本身。

### 6. 触点极简与唤起式服务
人类（学习者）出场时刻最小化，且服务是唤起式（pull）而非推送式（push）——保护动机带宽。本项目：全程仅三触点 + 默认零推送。

### 7. 死法预演
设计阶段显式列出最可能的失败模式（死法）与对策，运行后回填验证预测。两份设计的死法总表（组织 D1–D8、App A1–A10）即此机制的产物。

### 8. 政策继承块
把不可违反的约束写成可机读的政策清单（policy id），组织与组件自动继承、逐条可审计。见 org-design §六.3 的 policies 块。

### 9. 生成链定位
理论 → 规范 → 元组织 → **特化元组织（英语教练局）→ 运行时载体（App）** → 临时组织（每次微会话）→ 产物（学习账本）。本项目当前处于：特化元组织已定、运行时载体设计已定（v0.2）、待实施。

### 10. goal-keeper（守门人）
人类守门人：价值函数与不可委托裁决的唯一持有者。本项目 = 学习者本人——学什么、什么算学会、何时停，全部由学习者裁定；AI 组织只呈交选项与证据。

## 术语速查

| 术语 | 含义 |
|---|---|
| 账本 | 六件状态文件（learner-state / chunk-ledger / journal / session-log / error-book / weekly-review）+ corpus/ + queue/，产品的本体 |
| 语块（chunk） | 2–6 词的自然共现单位（搭配/短语/句式/习语），本项目最小学习记账单位，非单词 |
| 档位 B0/B2/B5/B15 | 微会话时间预算分档：纯听 / ≤2min / 3–5min / 10–15min |
| 预切队列 | 教练官预先切好的即取即用微任务包（分档位、带水位线），唤起零启动成本的关键 |
| 预嵌判定（T0） | 队列项生成时即附带判读官独立产出的评分细则，离线可判 |
| 消费锁 TTL | 队列项的"设备+心跳时间戳"锁，心跳超时自动释放，设备失联不阻塞队列 |
| 陈旧读 | 多设备同步未达时读到旧账本；处理原则：显式标注，宁可重复不可丢失 |
| 三源循环 | 语感训练调度配比：i+1 新输入 ~55% / 语境复现 ~25% / 输出判定 ~20%（可调） |
| I-DISC | 见机制 §3；工程化 = 判读请求为独立 API 调用，不含出题上下文 |
| BYOK | Bring Your Own Key——用户自带模型 API 密钥，无账号无内购 |
| coach_core | 纯 TypeScript 核心层包（账本 I/O / 调度 / 队列 / 合并），零 UI 依赖，可无头测试；CLI 壳可直接复用 |
| 双模运行 | 单机是基线形态（零联网全功能），同步是可选叠加层 |
| 判据三级 | 验收判据的强度分级：判定级（二值，够用起步）/ 方向级（好坏排序）/ 度量级（数值+期限），从左到右验证成本递增 |
| Status-Quo 对照 | 决策文体：把「维持现状」与各候选方案并排列死法对比后再裁决 |
