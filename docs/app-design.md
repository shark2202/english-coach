# AI 英语学习教练 App 设计（跨平台运行时载体 v0.3）

> **一句话**：这个 App 不是产品本体，产品本体是六件账本文件——App 只是让英语教练局在 iPhone 和 Mac 上跑起来的壳；壳用 Lynx（Vue 版）一套技术栈覆盖目标平台，账本契约保证任何时候换壳、加平台、甚至退回终端，学习进度都不丢。

> **项目归属**：本设计属独立项目 english-coach（/Users/mac/codes/english-coach）；文中引用的 specs/、proposals/、theory/ 路径均指 ai-native 理论仓（/Users/mac/ai-native），仅作版本锚引用，文件不在本项目内。设计所用机制的自带定义见 [kernel.md](kernel.md)——无需访问 ai-native 仓即可完整理解本设计。

> **修订记录**：v0.1（2026-10-13）初版；v0.2（2026-10-14）收编用户追加要求「纯单机可用 + 联网同步 + 设备间无缝切换」——双模运行原则（单机基线、同步可选叠加）、离线判定三级（预嵌/本地模型/联网补判）、无缝切换（轮次即会话状态 + Handoff + 消费锁 TTL + 陈旧读显式化）、死法 A9/A10、AC 扩至十一条；v0.3（2026-10-14）选型裁决收编——**优先 LynxJS（Vue 版），Ubuntu 延后或取消**（goal-keeper 裁决，推翻评估原判「Flutter 主选」）：coach_core 由纯 Dart 改**纯 TypeScript**（L1/L2/L3 单语言栈），Flutter 降为回退路径，新增死法 A11/A12，Phase 1 排序 iOS 先行去桌面风险。

## 一、命题与定位

**命题**：为 [组织设计](org-design.md)（english-coach-bureau 骨架 v0.1）设计 App。设备路线：**iOS + macOS 先行**（用户现有两设备），**Windows/Android 将来扩展，Ubuntu 延后或取消（v0.3 裁决）**。**运行形态（v0.2 追加）**：纯单机可用是硬约束（零联网全功能），联网同步是可选叠加（iCloud 先行、通用方案将来），目标是设备间**无缝切换**——会话中途换设备，续学点不丢、立即可续。

**在生成链上的位置**（落地框架 v0.2 第四章的域实例）：理论 → 规范 → 元组织 → **特化元组织（英语教练局，已落盘）→ 本 App = 该特化组织的运行时载体** → 每次微会话（临时组织）→ 学习账本（Verified 产物）。App 不重新发明组织机制，只把组织设计的四组机制（可恢复/碎片适配/语感循环/门禁度量）工程化。

**三条从组织设计直接继承的架构约束**：

| 组织不变量 | App 架构含义 |
|---|---|
| L-NOLOSS/L-RESUME（进度只认账本；每轮微落盘） | 账本文件是唯一事实源；App 内任何缓存/数据库都是派生物 |
| L-REFORM（组织可随时解散重建） | **App 可整体替换**：卸载重装、换平台、换实现，账本在即组织在 |
| 触点极简 + 唤起式（pull 非 push） | 默认零推送通知；启动成本是第一体验指标 |

## 二、总体架构：账本优先，App 是壳

```
┌─────────────────────────────────────────────────┐
│ L4 平台集成层：音频（TTS/ASR/后台播放）· 同步      │
│    （iCloud）· Widget/快捷指令/菜单栏/全局热键     │
├─────────────────────────────────────────────────┤
│ L3 壳层（Lynx·VueLynx UI，可整体替换）           │
│    iOS / macOS（Lynxtron）/（将来）Win·Android    │
├─────────────────────────────────────────────────┤
│ L2 AI 服务层：角色提示词（教练官/选材官/陪练官/     │
│    判读官）· BYOK · fresh-context 纪律 · 离线三级  │
├─────────────────────────────────────────────────┤
│ L1 核心层 coach_core（纯 TypeScript 包，零 UI 依  │
│    赖，可无头测试）：账本 I/O · journal 追加 · 记忆官│
│    调度算法 · 队列管理 · 会话状态机 · 合并逻辑      │
├─────────────────────────────────────────────────┤
│ L0 账本契约层（平台无关文件，产品本体）：           │
│    learner-state / chunk-ledger / journal /       │
│    session-log / error-book / weekly-review +     │
│    corpus/ + queue/（预切队列含离线音频）          │
└─────────────────────────────────────────────────┘
```

| 层 | 职责 | 可替换性 |
|---|---|---|
| L0 账本契约 | 状态与进度的唯一事实源；格式即接口 | **不换**（换=迁移） |
| L1 核心层 | 全部确定性逻辑（调度/队列/落盘/合并） | 随壳走，但必须无 UI 依赖 |
| L2 AI 服务 | 非确定生成与判定；provider 无关 | 换模型/换厂商不动 L1 |
| L3 壳 | 交互呈现 | **整体可替换**（含终端壳，见 §十） |
| L4 平台集成 | 各 OS 特有能力 | 每平台一套薄适配 |

**关键判决：记忆官的间隔调度是确定性算法（本地代码），不调 LLM**——调度要快、离线可用、零成本、可单测；只有生成（选材/陪练）与判定（判读）走 LLM。角色提示词与调度算法都作为账本目录内的版本化配置文件存放，可审计可回滚。

**双模运行原则（v0.2 增，用户要求「纯单机可用 + 联网同步、无缝切换」）**：**单机是基线形态，同步是可选叠加层**——不登录任何账号、全程无网，学习回路/调度/账本/音频照常运行（判定走 §六离线三级）；同步层（iCloud 或将来 Syncthing/WebDAV）只在用户显式开启后介入，其失效（无网/未登录/服务故障）**不降低单机功能一分**。反向同样成立：账本目录是同步的唯一载荷，同步工具随时可换而不触碰 App 内部——两层各自可逆。

## 三、技术选型

**主选（goal-keeper 裁决 2026-10-14）：Lynx（Vue 版，VueLynx）**——iOS/macOS 先行，Windows/Android 将来扩展，**Ubuntu 延后或取消**。完整证据与裁决记录见 [tech-eval-lynx-20261014.md](tech-eval-lynx-20261014.md)：评估原判「不替代 Flutter 主选」，其三项顾虑（Linux 断角 / Vue×桌面双早期 / 宿主自建成本）经裁决转为**已接受风险**，对策如下。

**已接受风险的工程化承接**：

| 风险（源自评估） | 对策 |
|---|---|
| Vue×桌面双早期叠加（VueLynx Alpha，桌面更新以 ReactLynx 为主线，而 Phase 1 恰需 macOS） | Phase 1 内部排序 **iOS 先行**（Vue 生态最成熟切片）、macOS 跟进；桌面受阻时三选项：等 VueLynx 桌面迭代 / Lynxtron+Web 产物临时过渡 / 上浮 goal-keeper 重估——不在关键路径硬闯 |
| Lynx 是嵌入原生应用的 UI 引擎，宿主与 L4 件原生自写量大于 Flutter 插件生态 | 宿主层做薄（只做桥接不做业务）；桌面复用 Lynxtron；L4 件按 Phase 渐进交付（先最小可用） |
| 平台路线依赖字节优先级（官方平台列表无 Linux） | Ubuntu 显式延后或取消（裁决在案）；若将来重启：Web 产物 + 薄壳（接受第二栈）或仅 CLI |
| 兜底 | **回退路径 = Flutter 壳**：账本契约与 coach_core 业务逻辑不变，壳层重写即可——「壳可替换」不变量兜底 |

**主选的真实收益**：L1/L2/L3 同为 TypeScript/Vue **单语言栈**（Flutter 方案是 Dart 核心 + Swift/Kotlin 宿主混栈）；Web 技术栈对将来 Web 壳直接复用；桌面（Lynxtron）与移动同栈；CLI 壳可直接复用 coach_core（Node 直跑）。

**备选对照（Status-Quo，判死法）**：

| 方案 | 死法 |
|---|---|
| A. **Lynx Vue 版（主选，裁决 2026-10-14）** | 已接受风险三条（上表）；L4 原生自写量与生态早期是持续成本 |
| B. Flutter 单代码库（回退路径） | 桌面深度集成依赖插件生态；Dart+原生宿主双语言栈；与 Vue 栈不亲和 |
| C. Tauri 2（Rust+WebView） | 移动端成熟度低于桌面；各平台 WebView 渲染差异；后台音频链路更费 |
| D. Kotlin Multiplatform + Compose | 桌面（尤其 macOS）成熟度与生态弱于移动侧；Swift 侧互操作负担 |
| E. Apple 双原生先行，其余将来重写 | 多平台目标下全线重做两遍；平台绑架（死法 A1）的直通车 |

**选型三问**：维度——目标平台覆盖率（4/5，Ubuntu 已裁减）、L4 集成件成本、生态成熟度、团队 Vue 熟悉度（本次裁决的隐含权重）；死法——Lynx 生态早期叠加（A11，对策三重保险：TS 核心解耦 / Flutter 回退 / CLI 壳）；可逆性——账本契约先行，**框架选错的最坏后果 = 重写壳层，进度零损失**，三重保险已列。

## 四、账本契约与微落盘工程

### 4.1 文件规范（L0，承接组织设计 §七并工程化）

| 文件 | 写入模式 | 冲突友好度 |
|---|---|---|
| `journal.jsonl` | **每轮交互 append 一行**（机器写，微落盘本体） | 最高（append-only，按行合并） |
| `session-log.md` | 会话末由 journal **派生重写**（人读摘要） | 派生物，可重建 |
| `chunk-ledger.md` | 变更时原子整体重写（写临时文件+rename） | 行级 LWW + 调度幂等重算 |
| `learner-state.md` | 教练官会话首尾重写 | 「下一步指针」段改为 journal 派生缓存 |
| `queue/`（预切队列） | 补切时追加，消费时标记 | 项级幂等 |
| `error-book.md` | 判读官追加 | append 为主 |

**结构性设计**：微落盘本体走 append-only 的 `journal.jsonl`（一行 = 一轮 = 时间戳+设备+档位+任务引用+轮次+结果摘要）；session-log、下一步指针全部从 journal **派生**。这同时满足：① 中断损失上界=一轮（L-RESUME）；② 多设备同步冲突退化为「并集合并」（append-only 天然可并）；③ 人读账本（OKF 友好）与机写高频更新不互相牺牲。

### 4.2 App 生命周期工程

- 每轮应答落定 → 立即 append journal（不等会话结束）；
- 进入后台（`didEnterBackground` 等）→ 当轮完成后安全停机，已落盘全保留——**不做后台偷偷续跑**；
- 冷启动自举 = 读 `learner-state.md` 缓存 + journal 尾行校验 → 直接呈现续学点，无向导无问答（碎片时间的敌人是启动成本）；
- 队列空且离线 → 取本地兜底包（选材官预置的通用复现包），不空转。

## 五、设备形态设计

### 5.1 iOS（iPhone，主战场：碎片微会话）

- **单列会话流**：练习即聊天，拇指可达应答；底部唤起条（继续 / 2 / 5 / 15 分钟 / 只要听）。
- **桌面 Widget + 锁屏 Widget**：今日复现语块 ×3 直接呈现，点击即入 B2——唤起成本压到一次点击。
- **快捷指令（App Intents）**：「嘿 Siri，英语两分钟」直达 B2。
- **B0 播放器**：锁屏/控制中心可控，兼容 AirPods 操作。
- 输入以选择/短答为主（单手约束）；长输出引导到 Mac（Handoff：同账本同队列，换设备续同一会话）。

### 5.2 macOS（深度输入与阅读）

- **三栏**：左=语境域与队列检视；中=会话主区/阅读区（衬线排版、行宽约束）；右=账本与错题本检视。
- **菜单栏常驻**：下拉即「2 分钟」快答入口；**全局热键**随时唤起。
- 键盘优先：造句/改写/复述的主战场（输出练习配比主要在此设备完成——对冲死法 D5 零食化）。
- 周度触点（T2）与仪表盘在此设备呈现完整版。

### 5.3 将来三平台的差异点（仅登记，不提前实现）

| 平台 | 特有集成 | 备注 |
|---|---|---|
| Android | 桌面 Widget + 快捷磁贴 + TTS/ASR 引擎抽象落地 | Lynx 壳复用 |
| Windows | 系统托盘常驻 + 全局热键（经桌面宿主） | 同步换 Syncthing/WebDAV |
| Ubuntu | **延后或取消**（v0.3 裁决）；若将来重启：Web 产物+薄壳，或仅用 CLI | CLI 壳不依赖 Ubuntu——coach_core 为纯 TS，Node 直跑任意平台 |

## 六、AI 服务层（L2）

- **BYOK（自带密钥）**：GLM / OpenAI / Anthropic / 任意 OpenAI 兼容端点 / 本地 Ollama（Mac 上即可用）。密钥入 Keychain。不建账号体系、不做订阅——同时规避商店审核与死法 A6。
- **角色提示词版本化**：教练官/选材官/陪练官/判读官四套提示词存账本目录（`prompts/`，带版本号），改提示词=改配置=可回滚，学习效果归因可锚定。
- **I-DISC 的工程化**：判读官调用是**独立 API 请求**——只含该练习项+学习者作答+评分细则，**不含陪练官的生成上下文**（可选异模型）；每次调用记请求摘要哈希入 journal，可审计「判读是否真 fresh」。
- **离线三级判定（v0.2 重构：双模的核心。I-DISC 在补切期已满足——练习由陪练官生成，评分细则由判读官独立生成后一并嵌入队列项，两份生成互不见上下文）**：
  - **T0 预嵌判定（零 AI、全离线）**：队列项补切时自带判读官预生成的参考答案/评分细则；B2 快答与理解检查做确定性比对或阈值匹配，结果标「预嵌」；
  - **T1 本地模型（可选安装）**：开放输出（造句/复述）的离线即时判定走本地小模型（macOS：Ollama/MLX；iOS：端侧路线见未决项），判读提示词与云侧同源同版本号；
  - **T2 联网补判**：T0/T1 低置信或标记待复核的作答，恢复联网后由云判读官后台补判并回写错题本；
  - **降级可见性**：三级判定结果在账本中均带级别标记，判定质量按级别分层统计——离线降级一旦悄悄拉低质量，仪表盘先看见（对齐逃逸分账思想：错误按发生层归因，这里按判定级别归因）。
- 断网时 B0/B2/B5/B15 全档从预切队列练（队列项自带材料与音频）；补切离线走 T1 本地生成，本地模型未装则退本地兜底包，不空转。
- **隐私边界如实声明**：练习内容会发送至所选模型提供商；账本与语料默认仅存本地+iCloud；判读官请求刻意最小化上下文，兼隐私与 I-DISC。

## 七、音频与 B0 档

- 预切队列项**预生成音频并缓存**（Wi-Fi/充电时批量），B0 离线可用；后台音频走平台后台播放模式（锁屏可控、息屏连续播放）。
- TTS 路线未决（见 §十二），但双模原则下顺序已反转（v0.2）：**本地引擎为基线**（Apple 系免费、离线可用、音质一般），云 TTS 为增强（Wi-Fi/充电时预生成缓存，命中即用）——纯单机场景音频永不缺位。
- 影子跟读（听→跟读→ASR 评测）为 Phase 2 能力：iOS/macOS 用系统语音识别框架起步，Android/Windows 再补引擎抽象。

## 八、同步与无缝切换（可选叠加层，v0.2 扩）

- **开启原则**：同步默认不开启——纯单机即完整产品。用户显式开启后，iOS+macOS 默认走 iCloud Drive 文件夹（免费、无服务端、两设备即同步；Files App 可见=用户可自管备份，对齐「账本是产品本体」）；将来三平台同一目录换 Syncthing / WebDAV / git——**目录即契约，同步工具可换**。
- **无缝切换机制**：轮次即会话状态——journal 尾行就是续学点，**会话不属于设备，属于账本**。iOS↔macOS 用 Apple Handoff（NSUserActivity）即时接力；非 Handoff 场景靠文件同步+变更通知：另一设备重读 journal 尾行，顶栏提示「上次会话 N 分钟前于 iPhone——继续？」。
- **消费锁 TTL**：队列项锁 = 设备 + 心跳时间戳；心跳超时（约 10 分钟无新轮次）自动释放——设备崩溃/被杀不永久阻塞队列，另一设备可安全接管。最坏情形 = 同一项练两遍，append-only 合账后去重标记，无数据损坏。
- **陈旧读显式化**：同步未达时界面如实显示「账本同步至 T 时刻（来源设备 X）」，不假装新鲜；陈旧续学点练出的轮次照常落盘合账——**宁可重复，不可丢失**。
- **冲突策略**：journal 并集合并（append-only 天然安全）；chunk-ledger 行级 LWW + 记忆官幂等重算调度；指针/统计从 journal 重算；双设备并发写退化为两次独立微会话合账，无数据丢失（AC 11 冲突注入实测）。

## 十、路线图与验收

### Phase 1（iOS + macOS MVP）

范围：coach_core（纯 TS：账本/journal/调度/队列/合并）+ VueLynx **iOS 壳先行、macOS 壳（Lynxtron）跟进** + 四角色 AI（BYOK，本地模型可选）+ B2/B5/B15 全档（含 T0 预嵌判定）+ B0 基础播放（本地 TTS 基线）+ 可选 iCloud 同步与无缝切换 + 周度触点页。**关键路径申报（v0.3）**：macOS 的 VueLynx 桌面成熟度是 Phase 1 最大不确定项——排序上 iOS 先行去风险，桌面受阻按 §三 对策表处置（等迭代 / Lynxtron+Web 过渡 / 上浮重估）。

**AC（可测试）**：

1. iPhone 冷启动到首个练习呈现 <2 秒（预切队列命中时）；
2. 练习中任意时刻杀 App，重开续学点=最后落盘轮，损失 ≤1 轮（随机杀 ×10 全过）；
3. iPhone 与 Mac 同账本交替使用无进度丢失（含双设备短时并发写场景）；
4. 断网唤起可练（B2/B5 从本地队列），判读正确标记「离线待判」并恢复后补判；
5. 判读官请求经日志验证不含陪练官上下文（I-DISC 工程实测）；
6. B0 后台连续播放 ≥30 分钟，锁屏可控；
7. 账本目录人工可读（六文件+corpus/queue 结构完整），删除 App 重装后从账本完整恢复（L-REFORM 产品级实测）；
8. **纯单机基线（v0.2）**：不登录 iCloud、全程飞行模式，B0–B15 全档可练（预嵌判定+本地 TTS+缓存音频），连续 72 小时离线使用零轮次丢失；
9. **无缝切换（v0.2）**：iPhone 会话中途（模拟杀 App）切到 Mac，续学点=最后落盘轮——Handoff 即时可达；仅靠文件同步 ≤1 分钟可达，且界面如实标注同步时点与来源设备；
10. **消费锁接管（v0.2）**：设备 A 练习中失联（心跳超时），设备 B 可接管同一队列项，合账零损坏；
11. **冲突注入（v0.2）**：自动化测试人为双端并发写 journal 与 chunk-ledger，合账零行丢失。

### Phase 2（扩平台 + 壳可替换证明）

Android/Windows 壳；**Node CLI 壳**（直接复用 coach_core，读同一账本跑 B2/B5，任意平台可用）——「壳可替换」从架构主张变为实测证据；Ubuntu 若重启：Web 产物+薄壳或仅 CLI（裁决点挂 goal-keeper）；影子跟读 ASR；Ollama 本地模型路线；自带材料导入。

### Phase 3（打磨）

统计仪表盘完整版、Widget/快捷指令全量、语境域商店、多学习者形态评估（挂未决项）。

## 十一、判断基准三问

- **维度**：① 体验层——冷启动时延、唤起点击数、杀 App 续学损失；② 学习层——沿用组织设计的修复率/输入量指标，App 不另造指标；③ 架构层——账本目录被非本 App 工具（编辑器/CLI 壳）读写的成功率。
- **死法**：v0.3 裁决后首要风险让位给 **A11（Lynx 生态早期叠加）**——VueLynx Alpha×桌面早期恰在 Phase 1 关键路径，对策三重保险：coach_core 纯 TS 与 UI 解耦、Flutter 回退路径、Node CLI 壳。A7 多平台过度工程与 A4 推送诱惑仍在册；A9（离线判定质量塌陷）值得单独盯：离线体验越顺滑，越容易忘记判定在降级——对策是把降级做成账本里的一等标记，让统计先于感觉。
- **可逆性**：账本契约先行使壳层整体可逆（换框架=重写壳，进度零损失）；框架选型因此按高可逆决策处理，不追求一次最优。唯一不可逆投入是开发时间——用 Phase 1 窄范围 MVP 控制赌注。

## 十二、未决项（留待 goal-keeper 裁决）

1. **分发形态**：App Store（审核+抽成+合规）vs TestFlight/自签（macOS 公证后直发）——影响 Phase 1 末期技术选型（如 Widget 需上架版本）。
2. **TTS/ASR 路线**：本地基线已定（v0.2 反转：本地为基线、云为增强），云增强的配比与预算上限待定。
3. **本地模型路线（v0.2 升格为双模核心决策）**：macOS 侧 Ollama/MLX 选型；iOS 端侧模型能否达到 T1 判定质量线——不达标的档位宁可只开 T0+T2，不硬上。
4. **App 命名与开源/商业化形态**（BYOK 架构两者皆可容纳）。
5. **多学习者**（家庭/班级）：本版单人，架构上账本目录按人分区即可，不做提前实现。
6. **Ubuntu 终局**（v0.3 新增，goal-keeper 裁决点）：延后 vs 取消。若将来重启，路径 = Web 产物 + 薄壳（接受第二栈）或仅 CLI——届时按判断基准三问重估。
