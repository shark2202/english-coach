# 处理流程 v0.1

## 零、口径适配与边界（明示，不静默套用）

**本项目的「由人执行的流程」指谁**：卡内处理流程是**人员模型**，描述由人执行的业务流程。本项目是单人自用教练 App，真正执行流程的「人」有两类——人类学习者，与充当组织成员的 AI 教练角色（org-design §二 已把它们画成组织结构图的角色表）。**两者都进泳道**：学习者是唯一的意图来源，AI 角色是流程的执行者。

**三条硬边界（卡内 B 段）**：

| # | 边界 | 本图如何遵守 |
|---|---|---|
| B1 | 不画系统内部逻辑与系统间活动 | 网络可用性、缓存命中、音频解码等**一律不进本图**，属批次 9 系统流程。本图的判断只在「角色之间能否拿到某物」这一层 |
| B2 | 不描述系统对用户操作的响应细节 | App 呈现什么、按钮在哪、屏幕如何切换，全部归 `17-use-case.md` 与批次 8 的 DAR。本图只写「谁在什么时候把什么交给谁」 |
| B3 | 分支超过 7±2 时改用决策树 | L1 的两个判断**只出框不展开分支**，分支逻辑引用 `07-decision-tree.md` 的树号，本图不重复定义 |

**泳道只放角色，不放系统**（卡内 E2）。语料局的选材官与陪练官**不占泳道**：二者在 L1 中唯一出场是「后台补切」，按卡内 E4 用**中间启动的事件符号**表示（见 §二 事件框），因为把两条后台支线画成泳道会把 4 条泳道撑到 6 条、把 L1 步骤撑破 7±2。

## 一、触发器、终止状态与会话状态转变

### 1.1 触发器与终止状态

| 项 | 内容 | 对齐 |
|---|---|---|
| **触发器（起点事件）** | 学习者发出唤起——`继续` / `2分钟` / `5分钟` / `15分钟` / `只要听` 六条口语指令之一（org-design §4.2） | 决策树 §三 的 `◎ 唤起（学习者给定档位）` |
| **终止状态 A（正常）** | 会话状态 = **已完成**；下一步指针已更新；队列水位已回写 | 决策树 §三 `▭【开练】` 之后的会话末动作 |
| **终止状态 B（Safe Halt）** | 会话状态 = **已中断**；当轮作废；已落盘全保留；下一步指针**保持指向中断前最后落盘轮** | org-design §4.2「`停`：当轮作废，已落盘全保留」 |
| **终止状态 C（空转）** | 会话状态 = **已中断**；无练习项可取，给出队列空提示并登记补切；**不重试** | 决策树 §三 `▭【空转提示】` |

**范围外的上下文步骤**（卡内 B 段「漏掉范围外前后步骤会界定不了边界」）：本流程的**前一步**是学习者「产生碎片时间的意图」，**后一步**是「下次唤起时读到的续学点」。二者都是范围外上下文，本图只画边界不画内容——边界处的输入是 journal 尾行与 learner-state，输出是 journal 追加行与 learner-state 重写。

### 1.2 会话三态的转变事件——收口状态表 §零 的甩挂账

`04-state-table.md:35` 明确把会话排除在建表之外，理由写的是「转变事件属批次 7 流程模型范畴」。**这就是那笔挂账**，本节以转变表形式还清：

| 初 ＼ 标 | 进行中 | 已完成 | 已中断 |
|---|---|---|---|
| **（新建）** | **唤起并开练** | 无 | 无 |
| **进行中** | 自环：每轮微落盘 | **档位时长用尽 / 队尾消费完** | **Safe Halt / 队列空 / 设备失联超时** |
| **已完成** | 无 | 无 | 无 |
| **已中断** | 无 | 无 | 无 |

| 代号 | 触发事件 / 条件 | 说明 |
|---|---|---|
| 唤起并开练 | 教练官取到至少 1 个练习项并加锁 | 建会话记录；B0 档例外——见 §六 |
| 档位时长用尽 | 累计交互时长达到该档预算（B2 ≤2min / B5 3–5min / B15 10–15min） | B0 **无时长闸门**，改用播放结束或学习者喊停 |
| 队尾消费完 | 消费锁指向的练习项已消费完成 | 队列已空则并入「队列空」分支 |
| Safe Halt | 学习者说 `停` | **当轮作废**，但此前已落盘的轮次全部保留（L-NOLOSS） |
| 队列空 | 该档位无可取项且兜底包不存在 | 并入决策树 §三 `▭【空转提示】`，登记补切，**不重试、等下次唤起** |
| 设备失联超时 | 心跳停止且设备失联 | 与练习项表的**复活路径①**（心跳超时释放）同源；另一设备可安全接管 |

**两处「确认无」及理由**：

- **已完成 → 已中断：确认无。** 完成的会话不再回退——Safe Halt 只对进行中的会话有意义，否则「已完成」这个终态就不诚实，等于把「我练完了」和「我半途跑了」混为一谈。
- **已中断 → 进行中：确认无。** 续学是**新会话**（触发器重新触发一次唤起），不是把旧会话复活。这条与练习项表的「锁定 → 可取（TTL 释放）」不同：练习项是可复用的资源，会话不是。

### 2.2 两个判断为什么在 L1

卡内 E1 说 L1「通常无决策」。本图保留 D1/D2 两处，理由是**两者的分支全部收敛**：D1 的「解析不出」降级到默认档后，仍走 1.3；D2 的「无续学点」走首练，仍走 1.4。它们**不产生平行的端到端分支**，只改变进入后续步骤时的档位与起点。**分支逻辑本身归决策树**——这正是卡内 B3「分支多时改用决策树」在本项目的落地方式。

| 判断 | 问题 | 分支去向（引用，不重述） |
|---|---|---|
| **D1** | 唤起指令能解析出档位吗？ | 决策树 §三 `◎ 唤起（学习者给定档位 B0/B2/B5/B15）`；解析失败按默认档 B5 处理（org-design §三 会话自举协议第 ③ 步） |
| **D2** | journal 尾行能定位到续学点吗？ | 决策树 §一 冷启动自举的 `◇ 存在续学点？`，四个叶子（续学 / 首练 / 引导 / 首次运行） |

## 三、跨角色交接泳道契约（本批次收口项 2）

四条泳道之间只有 **5 处交接**。每处交接都要回答三个问题：**交什么**（载荷）、**凭什么保证**（约束）、**交接失败怎么办**（补偿）。**交接失败的处理规则一律不在本图定义**——那属系统流程（批次 9）。

| # | 交接 | 载荷 | 约束 | 失败去向 |
|---|---|---|---|---|
| **X1** | 记忆官 → 教练官 | 今日复现集（语块 id 列表） | 记忆官**只写 chunk-ledger 调度栏**；复现集是派生结果不是配置 | 空集不阻断，教练官按无织入开练 |
| **X2** | 教练官 → 学习者 | 练习项内容（材料 / 题目 / 音频） | 取包时**加消费锁**（设备 + 心跳时间戳），不现场生成、不问问题 | 取不到项走决策树 §三 的降级链 |
| **X3** | **学习者 → 教练官 → 判读官** | 作答内容 + 题目标识 | **I-DISC：判读请求载荷不得含陪练官上下文**（出题过程的提示、生成轨迹、候选答案） | 载荷越界即为工程缺陷，走 `17-use-case.md` UC-07 的异常 EX1 |
| **X4** | 判读官 → 教练官 | 判定结果 + 反馈三栏 + 错误条目 | 判读官**只写 error-book 判定栏**，不出题 | 低置信走「待复核」，不阻断训练 |
| **X5** | 教练官 → 记忆官 | 复现信号（判定对错、掌握度变化） | 掌握度**上移须样本 ≥5 且锚位连续 2 次稳定** | 样本不足则**禁止上移**，维持当前档 |

### 3.1 X3 为什么是本流程的生死线

**死法 D4（自练自判固化错误语感）的唯一对策就是 X3 这一条箭头。** 它在流程上有三个不可省的条件：

1. **泳道分离**：出题（陪练官）与判读（判读官）不在同一条泳道——但陪练官不占泳道（§零），所以在图上表现为**判读官泳道与材料生产之间没有任何数据通路**，只有 X3 这一条有向箭头。
2. **上下文隔离**：X3 是**单向**箭头，无回边。判读官拿到作答后，回写的只有判定与反馈，**不把自己的推理过程写回给教练官的会话上下文**。若存在回边，判读官下一轮的判断就会带着上一轮的出题印象——隔离在流程层面被破坏。
3. **可验证**：AC5 要求「判读官请求经日志验证不含陪练官上下文」，因此 X3 的载荷边界必须是**可审计的接口契约**，而不是一句承诺。本流程只负责「箭头只有一个方向且指向独立泳道」，**日志审计的落地属系统流程与接口表**（`09-system-interface-table.md` 已登记禁止传输清单）。

## 四、L2 细化（2 处，均 <10 步）

### 4.1 L2-A：1.5 开练与微落盘（交互档 B2/B5/B15）

> 层级号 `1.5.n`：L1 第 5 步的细化。**B0 档不走本 L2**（见 §六）。

```
◎ 进入 1.5（交互档，教练官泳道）
 │
 1.5.1 呈现本轮材料（音频或文本）
  │
 1.5.2 学习者作答或继续输入
  │
 1.5.3 ◇ 本轮已结束？ ── 否 ──► ↩ 1.5.1（继续本轮）
  │        │ 是
 1.5.4 ▼
  │
 1.5.5 **微落盘**：向 journal 追加一行（DD101–DD111）
  │        ← 卡内语义：这一步就是 L-RESUME 的工程支撑
 1.5.6 ◇ 学习者还要下一轮？
  │        ├── 否 ──► ◇ 说「停」？
  │        │            ├── 是 ──► ▭ Safe Halt：作废当轮，返回 L1 的 1.8
  │        │            └── 否 ──► ▭ 档位时长用尽，返回 L1 的 1.8
  │        └── 是 ──► ◇ 本档预算内还有时间？
  │                     ├── 否 ──► ▭ 档位时长用尽，返回 1.8
  │                     └── 是 ──► ◇ 学习者说「太难了」/「太简单了」？
  │                              ├── 是 ──► 记难度反馈 → 即时降/升档
  │                              │         → 若仍在预算内 ↩ 1.5.1；若已超时 ▭ 返回 1.8
  │                              └── 否 ──► ↩ 1.5.1
```

**9 步，未超 L2 的 10 步上限**（卡内 E1）。要点：

- **1.5.5 微落盘是本流程最不可省的一步。** org-design §三：「不是会话结束才写，而是每轮交互结束即更新」。删掉它，L-RESUME 的「中断损失上界 = 一轮」立即失效，AC2 与 AC9 同时失效。
- **难度反馈是「即时」的**：学习者说「太难了」，**在下一轮开始前**生效，不等会话结束、不等周度触点。这是唤起协议区别于周度 T2 触点的地方——**唯一的例外是学习者已经处在当轮的中间，此时反馈只对下一轮生效**（当轮作废是 `停` 的专属语义）。

### 4.2 L2-B：1.8 收尾记账（会话末）

```
◎ 进入 1.8（教练官泳道）
 │
 1.8.1 重写 session-log 当前行（人读摘要，由 journal 派生）
  │
 1.8.2 更新下一步指针 = 最后一条落盘轮 + 下一档建议
  │
 1.8.3 ◇ 本会话是 Safe Halt？
  │        ├── 是 ──► 1.8.4 指针保持指向中断前最后落盘轮
  │        └── 否 ──► 1.8.5 指针推进到下一步
  │
 1.8.6 判定与错题回写（X4 已送回的判定）
  │
 1.8.7 回写复现信号给记忆官（X5）
  │
 1.8.8 ◇ 该档位队列水位 <2？
  │        ├── 是 ──► 登记补切任务（后台，永不阻塞唤起）
  │        └── 否 ──► ▭ 会话结束
```

**8 步。** 1.8.3 的分支是 Safe Halt 的**流程级兑现**：指针「保持」而非「推进」，与 org-design §4.2「当轮作废，已落盘全保留」逐字对应。

## 六、B0 档的 0 轮会话在流程中的位置（本批次收口项 3）

**B0 是唯一一条绕开 1.5–1.7 三步的支路。** 它不是「更短的会话」，而是**另一条路径**：

```
                    ┌── B2/B5/B15 ──► 1.5 开练落盘 ──► 1.6 ──► 1.7 ──┐
  从 1.4 取预切包 ──┤                                                  ├──► 1.8 收尾记账
                    └── B0 ──────────► 1.5-B0 仅播放（0 轮） ─────────┘
                                          │
                                          ├─ 无 1.6 收卷：无作答可判
                                          └─ 无 1.7 判读：不产判定、不入错题本
```

**为什么 B0 不经过 1.6/1.7，流程上不会断裂**：

| 通常的流程完整性要求 | B0 的处置 | 依据 |
|---|---|---|
| 每条路径都要到达终止状态 | B0 支路直接汇入 1.8，到达同一终止状态 | — |
| 交接不得悬空 | X1（复现集）B0 **不用**——纯听不需要织入复现语块的复现任务；X2/X3/X4/X5 在 B0 支路上均无发生，**是「不发生」而非「悬空」** | org-design §4.1「纯听或影子跟读（零交互）」 |
| 收尾记账不可省 | B0 仍执行 1.8——但记账内容不同，见下 | L-NOLOSS |

**B0 在 1.8 的记账差异（流程级）**：

- 追加**一行** journal，`DD107 轮次序号 = 0`（数据字典 `03-data-dictionary.md:46` 已明载此取值约定）；
- **不推进下一步指针**——B0 不消费难度锚，继续指向原续学点；
- **不触发 X5 复现信号**——B0 不产判定，故不驱动掌握度升降。

**0 轮会话为什么仍然是一个完整的流程实例**：它有触发器（1.1）、有分支点（1.4 的档位分支）、有终止状态（1.8 → 已完成），且**它的完成判定不依赖交互轮次**。「轮次」是 `交互轮次` 对象的基数下界（BDD 关系 2.1 的 `0..n`），不是流程实例的完整性条件。BDD 关系 2.1 的业务规则已明写「**0 必须允许**」。
