# 数据流图（DFD）v0.1

> **一句话**：这张图回答的不是「有哪些数据」，而是「训练数据从哪来、被谁改写、改写后流到哪去、载体是什么」——它是 `02-business-data-diagram.md`（谁和谁有关系）的动态对偶，也是 `11-system-flow.md`（先做哪一步、失败怎么办）的数据前置。

---

## 零、口径声明（三条边界，先说清本图不做什么）

### 0.1 与 BDD 的分工（卡内 A2 强制区分）

| | BDD（`02-`） | 本图 |
|---|---|---|
| 回答的问题 | 这些**对象**之间是什么关系、基数多少 | 这条**数据**被哪个流程改写、从哪流到哪 |
| 分组依据 | **业务域**（学习内容/学习过程/学习者/运行时） | **写者与生命周期**（事实追加流 / 调度区 / 生产区 / 派生区 / 交换区） |
| 时间维度 | 无（静态结构） | **同样无**——见 §0.3 第一条警告 |
| 表达手段 | 关系线 + 基数 | 流程圆框 + 数据流线 + 存储区双线框 |

**本图没有复制 BDD 的证据**：本图的 9 个存储区**不是**按 BDD 的 21 个对象一一对应建立的，而是按「**谁写、何时写、能否重算**」重新切分。例：BDD 把「语块」与「语块复现」分列两个对象（关系 1.3），本图把二者合并进同一个存储区 `D2`——因为它们**由同一步骤在同一时刻写入**，拆开会让图上出现一条永远为空的流。

### 0.2 关键对象的选取（卡内 B 段警告二：试图记录每一个数据流 → 没人看得完）

卡内明确警告「只画关键对象的数据流」。本图的取舍规则：

| 等级 | 对象 | 是否成流 |
|---|---|---|
| **主线（成流）** | 交互轮次 / 判定 / 语块与调度 / 练习项 / 队列 / 能力画像 | ✅ 独立数据流 |
| **随流携带（不成流）** | 语境域、材料、结构标注、术语、错题、提示词、消费锁、同步游标 | ⬜ 以 `<对象.字段>` 标注法随主线流出现（卡内 E1 规定：「只传字段子集时用 `<对象.字段>` 表示法；字段太多就记对象流」） |
| **仅登记（不成流）** | 学习者、目标锚、周度复盘、设备、语块复现的独立形态 | ⬜ 见 §四 回指表 |

### 0.3 本图不做的四件事

1. **不表达顺序**。卡内警告「试图在 DFD 中表达顺序」——DFD 无时间维度，数据存储区介入后各流程可发生在完全不相关的时间。顺序、时序、并发、异常补偿一律交给 [系统流程](11-system-flow.md) 与 [处理流程](16-process-flow.md)。
2. **不画决定框**。卡内：「DFD 不显示决定」。所有分支判断（判定级别选择、队列降级、同步失败处理）的唯一权威在 [决策树](07-decision-tree.md) 与决策表。本图中凡形似分支的地方，均为**两个各自独立的流程读取同一个存储区**，不是条件跳转。
3. **不画界面呈现**。壳层把数据显示出来不是数据流。「数据被读取以呈现」记为 §五 的**使用**动作，不产生流线。
4. **不表达角色与写权限**。教练官/记忆官/判读局的单写者约束属角色权限矩阵（批次 6）。本图只在需要时标注**步骤的账本写者**（见 §六 L2-2.3 注）。

### 0.4 流水线的选择（卡内 B 段「不要在以下情况使用此 skill」自查）

卡内列了三种 DFD 无增量价值的情形。逐条自查本项目：

| 卡内「不适用」情形 | 本项目是否命中 | 处置 |
|---|---|---|
| COTS 产品只作简单配置 | ❌ 未命中 | 项目未实现，且 L0 账本契约是自研设计 |
| **流程本质线性且已有简单 BDD，DFD 视角冗余** | ❌ **未命中**——但这是最需要说明的一条 | 本项目有 13 个外部系统、4 棵决策树、异步后台补切、跨设备合账、**三级派生重算**。「一条线性主干 + 一个简单 BDD」不成立 |
| 单一用户组、流程简单（输入给输出） | ❌ 未命中 | 单人 ≠ 单流程组；且 ASR/TTS/同步/AI 四类外部依赖各有独立失效路径 |

**结论：DFD 在本项目有增量价值，理由是「同一批数据被多条互不相识的流程共享」**——这正是卡内 A2 场景 1（「多个干系人组各管一段流程、却共享同一批核心数据」）。

## 一、确定业务数据对象与数据存储区（卡内 E1）

**逻辑存储区划分**（卡内：「数据存储区是概念性的逻辑存储，不代表物理库」）：本图的存储区**恰好与 L0 账本文件对齐**，因为本项目的账本契约本身就是被冻结的产品级接口（app-design §二「L0 不换」）。这不是巧合，而是本项目少有的「物理即概念」情形——已在此明示，避免读者误以为本图主张物理布局。

| # | 数据存储区 | 物理落点 | 承载的 BDD 对象 | 可否重算 | 分组 |
|---|---|---|---|---|---|
| **D1** | 事实追加区 | `journal.jsonl` | 交互轮次、判定 | ✖ 事实源 | 事实追加流 |
| **D2** | 语块调度区 | `chunk-ledger.md` | 语块、语块复现 | ◐ 事实栏可保留、调度栏须重算 | 调度区 |
| **D3** | 状态档案区 | `learner-state.md` | 学习者、目标锚 + 下一步指针 | ◐ 指针可重算 | 调度区 |
| **D4** | 语料区 | `corpus/`（含音频） | 语境域、材料、结构标注、术语 | ✖ 事实源 | 生产区 |
| **D5** | 预切队列区 | `queue/` | 预切队列、练习项、消费锁、补切任务 | ✖ 事实源（含**已发生的**锁与消费记录） | 生产区 |
| **D6** | 会话统计区 | `session-log.md` | 会话、统计量 | ✔ 一级派生 | 派生区 |
| **D7** | 错题区 | `error-book.md` | 错题 | ◐ 本体为事实、修复标记为派生 | 派生区 |
| **D8** | 能力画像区 | 画像快照 | 能力画像、维度掌握度 | ✔ 一级派生 | 派生区 |
| **D9** | 周度触点区 | `weekly-review.md` | 周度复盘 | ◐ 草稿为派生、裁决记回为事实 | 派生区 |

**三层可重算性分级（本图最有价值的产出之一）**：

```
D1 journal ──全量/增量──► D6 统计 · D7 错题修复标记 · D8 画像 · D3 指针
   （一级派生：可冷启动全量重算，兜底成立）
D2 事实栏 + D1 ──────────► D2 调度栏
   （二级派生：必须事实/派分栏，否则重算无处落地——见 §七 缺口 ①）
D4 corpus · D5 queue ────► 不可派生
   （事实：只能靠 git/备份，不靠重算）
```

这条分级是 [挂账 3](11-system-flow.md) 的数据层依据，也是接口表 §五「指针/统计 从 journal 重算」能成立的前提。

## 二、确定流程（卡内 E2：借处理流程/系统流程/用例的步骤名；命名「动词+宾语」）

L1 取 6 个流程（7±2 下限内）。为何不画更多：`P2 生产训练物料` 内部含**四个互不可见上下文的 AI 角色调用**，把它们压在一个框里已经是最粗的合法粒度，再拆会突破上限——故改为 L2 分解（卡内：「流程数 >7±2 时分层（L1 主功能，L2/L3 细化）」）。

| # | 流程（动词+宾语） | 主要写者 | 自动/手动 |
|---|---|---|---|
| **P1** | 编排并交付会话 | 教练官（`learner-state.md`）/ 记忆官（`chunk-ledger.md` 调度栏） | 自动 |
| **P2** | 生产训练物料 | 选材官 + 陪练官 + 判读官（提示词） + TTS | 自动（后台） |
| **P3** | 执行判定 | 判读官 / 预嵌细则 | 自动 |
| **P4** | 登记派生量 | 教练官（派生重算） | 自动 |
| **P5** | 维护队列水位 | 教练官 + 语料局 | 自动（后台），可由开发/运维侧手动触发 |
| **P6** | 合账跨设备账本 | 教练核心合并逻辑 + 记忆官 | 自动（事件触发） |

⚠️ **P1 内含两个不同写者**（教练官写 `learner-state.md`、记忆官写 `chunk-ledger.md` 调度栏）。DFD 不表达写权限，但此处写者不一致是**有业务后果的事实**（单写者约束），故在 §六 L2-1.3 显式标注步骤级写者，避免后续读者误以为 P1 是单写者步骤。

## 三、确定外部实体（卡内 E3：从生态图取系统、从组织结构图取人）

9 个外部实体，全部来自 [生态图](08-ecosystem-map.md) 的 13 个系统 + 组织结构图中的「学习者」。**每个实体都有输入或输出数据流**（卡内 E3 完成标准）。

| # | 外部实体 | 类型 | 生态图来源 |
|---|---|---|---|
| **E1** | 学习者（goal-keeper） | 人 | 组织结构图 §二 |
| **E2** | 云 LLM provider | 系统 | 组 2 |
| **E3** | 本地模型（T1） | 系统 | 组 2 |
| **E4** | TTS 引擎 | 系统 | 组 3 |
| **E5** | 同步通道（iCloud Drive ⊘ / Syncthing / Handoff） | 系统 | 组 4（可选叠加层） |
| **E6** | 开发/运维侧（文本编辑器 / Node CLI 壳 / git / 补切任务脚本） | 组 | 组 5 |
| **E7** | 唤起入口（Widget / 快捷指令 / 菜单栏 / 全局热键） | 系统 | 组 3 |
| **E8** | Keychain 凭据 | 系统 | 组 2 + 组 3 |
| **E9** | 后台音频播放 | 系统 | 组 3 |

**本图的系统边界**：内 = L0 账本契约 + L1 教练核心 + L2 AI 服务层 + L3 壳层（生态图组 1）；外 = 上表 9 个实体。

**两处边界处置（显式，避免与生态图打架）**：

- **账本文件 I/O（生态图组 3）在图中不是外部实体**。它是存储区的**读写介质**，每个流程经它落盘。若把它画成实体，会迫使图上出现 `外部实体 → 存储区` 或 `实体 ↔ 实体` 的违规连线——违反卡内核心约束「外部实体与数据存储区之间不能直接相连」。故本图的「载体」列已经承担了介质信息。
- **ASR 引擎（生态图组 3）本期不进 L1 主线**。它是 Phase 2 的影子跟读能力（app-design §七），本期 B0 为「纯听」。为遵守卡内「不记录每一个数据流」的警告，本图不画其往返；其回指见 §七 表。

## 五、数据流账（卡内 E4：每条流穿过流程；本项目追加要求：标注来源 / 终点 / 载体）

**载体取值域**：`文件`（账本文件，跨进程/跨设备可持久）· `内存`（进程内结构体，不跨设备）· `网络`（HTTP/API 调用）。后两列给出具体落点。

### 5.1 会话编排与交付（P1）

| ID | 数据流 | 来源 | 终点 | 载体 | 规模 | 备注 |
|---|---|---|---|---|---|---|
| F1 | 唤起意图（继续/2/5/15/只要听/太难/太简单/停） | E7 唤起入口 | P1 | 内存 | 5–10 次/日 | **用户动作不建模为流程**，只作数据源（卡内：DFD 不表达用户活动） |
| F2 | 唤起意图（App 直启） | E1 学习者 | P1 | 内存 | 同上 | 同上 |
