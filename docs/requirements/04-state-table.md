**排除 13 个对象**（卡内「只有两三种状态、转变线性无分支不值得建表」）：

| 排除对象 | 理由 |
|---|---|
| **交互轮次** | **append-only 不可变**——落盘后无任何字段会变，不存在状态空间 |
| **消费锁** | 生命周期是练习项「锁定」状态的附属；单独建表会与练习项表重复（卡内：不重复建模） |

| 语境域 / 语块复现 / 目标锚 / 周度复盘 / 设备 / 预切队列 / 提示词 / 学习者 | 状态少或转变线性，建表收益低于阅读成本 |

**建模口径偏离一处（明示）**：卡内要求「状态相互排斥」。「退步中」与「熟化等级」天然重叠（一个自动化中的语块可以同时在退步）。**本轮不把退步设为独立状态**，而以 DD609 衰减标记作为**转变的条件**而非状态——熟化三态互斥，退步体现为向下箭头。此为明示偏离，非静默处理。

**「无」格逐一确认（卡内警告：轻率标「无」会误杀复活路径）**：

- 待补切 → 锁定：**确认无**。未通过补切质检的项不允许被锁定，否则离线判定无细则可依。
- 已消费 → 可取：**确认无**。若判定被降级复查击穿，走「已消费 → 作废 → 新建项」而非复活旧项——**避免旧版预嵌细则与新判定标准混用**。此为明示的设计取舍，非遗漏。
- 作废 → 任何：**确认无**。作废项不可复活；难度回退需要同类材料时走新建。理由同上（避免污染旧标注版本）。

## 四、错题（ErrorEntry）

| 初 ＼ 标 | 未修复 | 待验证 | 已修复 | 复发 |
|---|---|---|---|---|
| **未修复** | **同类错误再犯** | **首次入本** | 无 | 无 |
| **待验证** | **验证未通过** | — | **验证通过** | 无 |
| **已修复** | 无 | 无 | **持续观察** | **同错二犯** |
| **复发** | 无 | **重新验证** | **再次验证通过** | **再次二犯** |

| 代号 | 触发事件 / 条件 | 说明 |
|---|---|---|
| 首次入本 | 判定结果为「错」或「不自然」 | — |
| 验证通过 | 后续复现中同类错误**未再犯** | 对齐 org-design §5.3「同类错误第二次不再犯才算学会」 |
| 验证未通过 | 后续复现中同类错误**再犯** | 待验证 → 未修复，回到原点 |
| **同错二犯** | **已修复的错题再次出现同类错误** | **复活路径⑤，也是本轮最重要的发现** |
| 再次验证通过 | 复发后连续未再犯 | 二次修复（比首次严格） |

**「无」格确认（本表最关键的三格）**：

- **未修复 → 已修复：确认无，且必须禁止。** 这正是卡内警告的「轻率标无效会误杀复活路径」的反面——这里标无是**正确的**，因为 org-design §6.1 把「错题修复率（同错二犯率）」列为**核心指标**。若允许未修复直接跳到已修复，该指标恒为 100%，**指标作废**。
- 已修复 → 待验证：**确认无**。已修复项不主动回退；只有二犯才进入「复发」。
- 复发 → 复发：**允许**（持续二犯），每次再犯记一次，用于暴露「这个错误类型始终修不掉」。

**与组织设计的对应**：本表的「已修复 → 复发」边，使 org-design §6.1 的核心指标从「比例」升级为「可追的逐次事件序列」——否则只知道比例是 40%，不知道是哪四类错误在复发。

## 八、同步游标（SyncCursor）—— ⚠️ 本表修正了既有设计

| 初 ＼ 标 | 单机 | 同步中 | 已同步 | **同步失败** |
|---|---|---|---|---|
| **单机** | 无 | **用户开启同步** | 无 | 无 |
| **同步中** | **用户关闭同步** | — | **同步完成** | **同步失败 / 中断** |
| **已同步** | **用户关闭同步** | **下次同步开始** | — | **下次同步失败** |
| **同步失败** | **用户关闭同步** | **自动重试** | 无 | — |

| 代号 | 触发事件 / 条件 | 说明 |
|---|---|---|
| 用户开启同步 | 学习者显式开启同步开关 | 默认**不开启**——纯单机即完整产品（app-design §八） |
| 用户关闭同步 | 学习者显式关闭 | 三条来源（同步中/已同步/同步失败）均可关闭，**关闭后功能不减** |
| 同步完成 | 账本目录全量完成同步 | 进入「已同步」，界面可显示同步至时刻与来源设备（DD704/DD705） |
| 同步失败 / 中断 | 传输中断、冲突未解、凭据失效等 | 落第四态，**不得归入「同步中」或「单机」** |
| 下次同步开始 | 变更事件或兜底轮询触发 | 已同步态的自环，重入同步中 |
| 自动重试 | 失败后下一轮唤起 | **重试不提升状态**——失败态必须由一次成功同步才能离开 |

**⚠️ 本表发现既有设计的一处缺口**：数据目录的「同步状态列表」只列了**三态**（单机 / 同步中 / 已同步）。但同步失败时无法归类——

- 归「同步中」→ 界面永远显示同步中，学习者以为在同步其实早已失败——**这是死法 A10 陈旧读幻觉的新变种**；
- 归「单机」→ 失败被掩盖，账本已陈旧但界面显示「单机模式，功能完整」，同样不诚实。

**结论：必须新增第四态「同步失败」。** 本结论**在 A10 写作「同步状态显式三态」时即已成立**——A10 说的是「不假装新鲜」，而**把失败归入三态中的任何一个都是在假装**。⚠️ **现状对齐（2026-10-14）**：`app-design.md` §九 A10 的三态旧措辞**已由编排者改为四态**，与本表结论一致；`03-data-dictionary.md` v0.2 的「同步状态列表」亦已含 DD703 四态与「同步失败」，故原「建议同步更新 `03`」这条待办**已完成**，本表与上游无残留缺口。

**「自动重试」不提升状态**这条是本表新增的规则：若无此约束，一个持续失败的同步会在「同步中 ↔ 同步失败」之间无限抖动，界面反复闪烁——**抖动本身也是一种噪音，会掩盖真正需要注意的状态**。

## 九、E6 完整性审查

| 审查问题 | 结论 |
|---|---|
| 是否漏了某状态（有意不设吗） | ⚠️ **发现一处**：同步游标原设计只设三态，缺「同步失败」。已补 |
| 能否跳过某状态 | 掌握度「生 → 自动化」**刻意禁止跳过**（§三），理由：否则 SM5 轨迹斜率不可解释、SM6 失效 |
| 终态能否被阻止 / 退回 | **三处必须可退回**：错题「已修复 → 复发」（§四）、语块/掌握度「自动化 → 半熟」（§三）、练习项「锁定 → 可取」（§一）。卡内警告「终态复活常被误杀」在此**三度命中** |
| 「无」格是否真会业务发生 | 全部 30 个「无」格逐一给了理由；其中「未修复 → 已修复」标无是**为保护核心指标**而刻意为之 |

**复活路径清单（5 条）**：

| # | 路径 | 若被误杀的后果 |
|---|---|---|
| ① | 练习项 锁定 → 可取（TTL 释放） | 设备被杀则队列永久阻塞，死法 A3 |
| ② | 练习项 可取 → 待补切（水位回收） | 队列无法重整 |
| ③ | 练习项 已消费 → 作废（判定降级复查） | **新发现**——离线判定塌陷时无法重练，死法 A9 无补救 |
| ④ | 判定 判定正确 → 待复核（置信下调） | 低质量判定无法批量召回，死法 A9 扩大 |
| ⑤ | 错题 已修复 → 复发（同错二犯） | **核心指标「错题修复率」恒为 100%，指标作废** |
