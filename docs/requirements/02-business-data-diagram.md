# 业务数据图（BDD）v0.1

## 零、输入契约缺口与口径声明

**卡内 E 段「必需输入」四条，本轮实到两条**：

| 必需输入 | 状态 |
|---|---|
| SME 访谈记录或业务术语清单 | ⚠️ **部分**——无正式访谈记录，以 goal-keeper 在本轮对话中的口头陈述 + 既有账本设计替代 |
| 已有生态图 / 处理流程 / 用例 / DAR | ❌ **缺失**——分别属批次 5/7，尚未产出。**故本图的对象发现只用了三条来源中的两条** |
| 现有系统数据模型 | ✅ 不适用——项目未实现，无既有系统 |

**此缺口的后果**：卡内 E6「这个对象还跟谁相关」「每对象六动作是否都有处理流程支撑」两项审查**无法完成**——后者需要流程与用例。已在 §六 明确标注为未完成。

**口径适配**：卡内对象数守则为「每张图 ≤7±2，超出则分组或拆图」。本项目对象数远超单图上限，故拆为 **4 张分域 BDD**，每张 4–6 个对象。

## 一、对象候选清单（E1 三条来源）

| 来源 | 提取到的对象 |
|---|---|
| SME 口头陈述 | 学习者、能力、训练、术语、哲学、管理、材料、结构标注、理解判定、语感、翻译损耗 |
| 既有账本设计（org-design §七 / app-design §四） | 语块、会话、日志、错题、队列、预切队列、消费锁、提示词、语料、journal 行 |
| 现有系统 | N/A（未实现） |

**按卡内 E2「对象 vs 字段」判据筛除**：

- **账本目录 → 剔除**。它是文件容器概念（`learner-state.md` / `journal.jsonl` 等），对应实现层而非业务数据对象。卡内开篇即明示「BDD 描述用户如何看待他们的数据……而 ERD 显示数据库架构中的实际实现」——把目录结构画进 BDD 是把实现当概念。⚠️ **代价明示**：同步游标因此需要独立成对象（见 BDD-4），否则 A10（陈旧读幻觉）的对策无处安放。
- **难度锚 → 不作独立对象**，并入「维度掌握度」。判据：它虽与材料/判定/画像三处相关，但**它是画像的状态组成部分而非关系的中转站**——独立成对象会触发卡内 B 段警告的「创建中间人对象」。
- **判定级别（T0/T1/T2）、能力维度、档位、结构标注类型 → 不作对象**，它们是**共享有效值列表**，归数据目录（见 `03-data-dictionary.md` 数据目录节）。

## 二、BDD-1 · 学习内容域（语境域 / 材料 / 结构标注 / 术语 / 语块 / 语块复现）

```
   语境域            材料            结构标注            术语
     │1               │1                 │n                  │
     │                │                  │                   │
     │n               │n                 │1                  │n
     ▼                ▼                  │                   ▼
   材料 ────────────────────────────► 结构标注 ◄────0..1─────┘
     │                                      │
     │1                                    │（术语陷阱标注指向术语）
     │n                                    │
     ▼                                      │
   语块复现                                 │
     ▲                                      │
     │n                                     │
     │1                                     │
   语块
```

| # | 关系 | 基数 | 业务规则 |
|---|---|---|---|
| 1.1 | 语境域 — 材料 | 一个语境域含 **0..n** 材料；每份材料恰属 **1** 个语境域 | 0 允许：域刚建立未选材 |
| 1.2 | 材料 — 结构标注 | 一份材料有 **0..n** 标注；每个标注恰定位 **1** 份材料 | **入队材料须 ≥1 标注**（F2 的入池条件；未标注材料不得进入预切队列） |
| 1.3 | 语块 — 语块复现 | 一个语块有 **1..n** 次复现；每次复现恰属 **1** 个语块 | ≥1：首次出现即记为复现史第 0 条 |
| 1.4 | 材料 — 语块复现 | 一份材料含 **0..n** 次复现；每次复现定位 **1** 份材料 | 这是 n:n 的合法关联对象，非中间人——它有自身字段（位置、语境、本次角色） |
| 1.5 | 术语 — 结构标注 | 一个术语有 **0..n** 个陷阱标注；每个陷阱标注可指向 **0..1** 个术语 | 0..1：非术语类的标注（限定嵌套、情态标记）无对应术语 |
| 1.6 | 语境域 — 语块 | 一个语境域有 **0..n** 语块；每个语块有 **1** 主语境域 | 主语境域唯一；其余语境由「语块复现」承载 |
| 1.7 | 语块 — 结构标注 | **0..n : 0..n**（一个语块可被多条标注命中，一条标注可覆盖多个语块） | 标注范围可能跨语块（如整段名词化链） |

**本域完整性审查（E6 部分完成）**：
- 「我们真的需要这个对象吗」→ 语境域 ✅（死法 D7 语料同质化的对策载体，多样性下限需要它作为计量单位）
- 「为什么允许 0」→ 1.1 与 1.5 的 0 已给理由；1.2 的 0 已给理由（未标注材料）——**但这构成一个待验证的完整性风险**：若「未标注材料」实际不可入队也不可读，则 0 应改为 1..n。⚠️ 挂批次 2 数据字典验证。
- 「每对象六动作是否有流程支撑」→ ❌ **无法完成**（缺处理流程/用例，批次 7）

## 三、BDD-2 · 学习过程域（会话 / 交互轮次 / 练习项 / 判定 / 错题）

```
   练习项 ────n────► 会话 ────0..n────► 交互轮次 ────1────1────► 判定
   │                              ▲                               │
   │n                             │1                              │n
   │                              │                               │0..n
   │0..1                          │                               ▼
   ▼                              └──────── 判定 ────n────0..n──► 错题
 消费锁                                                              ▲
                                                                     │n（修复验证）
                                                                     └── 后续判定
```

| # | 关系 | 基数 | 业务规则 |
|---|---|---|---|
| 2.1 | 会话 — 交互轮次 | 一个会话有 **0..n** 轮；每轮恰属 **1** 会话 | **0 必须允许**：B0 档「纯听/影子跟读」交互轮数为 0（org-design §4.1）——这正是 B0 落盘机制未决项的后果，此处先保住基数 |
| 2.2 | 练习项 — 会话 | 一个练习项被 **0..n** 个会话消费；一个会话消费 **1..X** 个练习项 | **n:n 刻意成立**：app-design §八 明载最坏情形「同一项练两遍」（消费锁 TTL 超时后另一设备接管）。若定为 1:1 则该降级策略无处安放 |
| 2.3 | 交互轮次 — 判定 | 每轮产生恰 **1** 条判定；每条判定恰来自 **1** 轮 | ✅ **例外已裁决（批次 7）**：`DD107=0` 的会话级落盘行（`DD107≥1`）**不是交互轮次实例**，故 2.3 不适用，该行不产判定。B0 的完成判定改由「退出条件命中 + 会话级落盘行」两条可检测条件承担（见 `17-use-case.md` UC-03） |
| 2.4 | 判定 — 错题 | 一条判定产生 **0..n** 条错题；一条错题来自 **1..n** 条判定 | 0：判定通过；n>1：一次输出含多处错误。「修复验证」靠错题被后续判定引用实现，故是 1..n 而非 1:1 |
| 2.5 | 练习项 — 消费锁 | 一个练习项有 **0..1** 把锁；一把锁锁住 **1** 个练习项 | 0：未消费或锁已超时释放 |

**本域基数中三处「刻意非 1:1」**：2.1（0..n）、2.2（n:n）、2.4（1..n）。这三条若被误改为 1:1，会分别击穿 B0 档、消费锁接管机制、错题修复验证——**是本次 BDD 最高价值的产出**。

## 四、BDD-3 · 学习者域（学习者 / 能力画像 / 维度掌握度 / 目标锚 / 周度复盘）

```
   学习者 ──1────n──► 能力画像 ──1────n──► 维度掌握度
     │                    ▲
     │0..1                │n（历史快照，current 标志位区分）
     ▼                    │
   目标锚                  │
     │
     └──0..n──► 周度复盘
```

| # | 关系 | 基数 | 业务规则 |
|---|---|---|---|
| 3.1 | 学习者 — 能力画像 | 一个学习者有 **1..n** 份画像；每份画像恰属 **1** 个学习者 | **恰有 1 份标 `current`**，其余为历史快照。留史的理由：SM5 要求呈现掌握度变化轨迹（含负斜率）——**不留史则轨迹不可计算** |
| 3.2 | 能力画像 — 维度掌握度 | 一份画像含 **1..X** 条维度掌握度；每条恰属 **1** 份画像 | X 初始取 6（BOM 未决项 6 的拟案），**上限不做硬约束**——能力维度粒度待批次 2 冻结后可能增减 |
| 3.3 | 学习者 — 目标锚 | 一个学习者有 **0..1** 个目标锚 | 0：T1 触点未执行。此时材料编排退化为通用兜底包（与 G4 的陈旧画像同一条降级路径） |
| 3.4 | 学习者 — 周度复盘 | 一个学习者有 **0..n** 份周度复盘 | 0：未到周度触点（T2） |

**本域是 BOM v0.3 新增需求的落点**：F7（能力画像）与 F8（判定难度锚）。3.1 的「恰一份 current」与 3.2 的「每维度一条」是「能力画像」这一概念成立的**最低结构条件**——若允许零份或零条，G4 的画像新鲜度判定将无对象可判。

## 五、BDD-4 · 运行时域（设备 / 同步游标 / 预切队列 / 消费锁 / 提示词）

```
   设备 ──1────n──► 消费锁 ──1────1──► 练习项（见 BDD-2）
     │
     │1
     ▼
  同步游标 ──1────n──► 交互轮次（陈旧读显式化的引用来源）
     │
     │（预切队列属学习者而非设备）
     ▼
  预切队列 ──1────n──► 练习项
     │
     │1
     ▼
   提示词（版本化，四套角色提示词）
```

| # | 关系 | 基数 | 业务规则 |
|---|---|---|---|
| 4.1 | 设备 — 消费锁 | 一个设备持有 **0..n** 把锁；每把锁由 **1** 个设备持有 | 心跳超时自动释放；持有数上限未定义 |
| 4.2 | 预切队列 — 练习项 | 一个队列有 **1..n** 项；每项恰属 **1** 个队列 | **水位线 ≥2/档**（org-design §4.3）；水位不足时登记补切任务，补切不阻塞唤起 |
| 4.3 | 同步游标 — 交互轮次 | 一个同步游标可对应 **0..n** 轮次 | 用途：界面标注「账本同步至 T 时刻（来源设备 X）」时，回指续学点所在轮次（A10 对策） |
| 4.4 | 设备 — 同步游标 | 一个设备持有 **1** 个同步游标 | 游标的四态（单机/同步中/已同步/**同步失败**）落在此对象上——⚠️ **这是剔除「账本目录」为对象所付出的代价，已显式承担**（v0.2.1 补第四态，与 DD703 同源） |
| 4.5 | 提示词 — 角色 | 四套角色提示词（教练官/选材官/陪练官/判读官），各自版本化 | 提示词版本入 journal 请求摘要，使「学习效果归因」可锚定到具体提示词版本 |

**边界案例显式记录**：`同步游标` 是否算业务数据对象存疑——它服务的是技术性需求（多设备一致性）。**保留它的理由**：A10（陈旧读幻觉）对策要求界面「如实标注同步时点与来源设备」，这是一条**干系人可见的业务规则**而非纯技术细节。⚠️ 若批次 5 生态图判定它纯属技术层，应降级为字段。
