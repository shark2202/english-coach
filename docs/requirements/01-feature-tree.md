# 特性树 v0.2

> **形态**：鱼骨图/石川图。主干 = 产品概念「在正确语感环境中看懂专业英语」，各级特性挂在主线上。
> **规模守则自检**：L1 = 9（≤9 ✅，已达上限，再增须先拆分）；每个 L1 的 L2 数 = 4–6（≤7±2 ✅）；层级 = 2（≤3 ✅）；全树无重复挂接 ✅。
> **口径适配**：卡内「管理人员的需求」来源，在单人自用项目中由**学习者本人以 goal-keeper 身份兼任**——已明示，非静默套用。
> **v0.2 变更**：新增 L1-9 能力建模（F7/F8 落地）。**难度相关特性重新归属**——原先「难度分带」在语料供给、「难度反馈」在会话调度、「语块间隔调度」在复习调度，三处各自为战且隐含同一份状态。v0.2 将**状态的归属**（能力画像）收进 L1-9，三处改为只管各自的动作。

## 四、两个新增特性的必要性论证

### 4.1 `L1-1 材料淘汰重整`（销毁）

语料不是只进不出的池子。难度带会随学习者水平上移，若无淘汰机制，旧材料会持续占用预切队列水位与语块调度配额，把新材料挤出队列——而队列空了正是死法 A3（App 空转）的触发路径。专业域尤甚：哲学与管理材料的专业性使「过期」比通用英语更快发生。

### 4.2 `L1-6 账本导出备份`（复制）

I-REFORM 的产品级实测（app-design AC7）要求「删除 App 重装后从账本完整恢复」。但**恢复能力的前提是账本曾被带出 App**——若账本只存在于 App 沙盒内，卸载即灭。此特性是 AC7 的前置条件，不是可选项。

## 五、E4 缺失特性审查

卡内 E4：逐节点审查，**只有 1–3 个子特性的节点**提示该层可能缺特性。

**本轮审查结果（v0.2 复核）**：9 个 L1 的子特性数分别为 6/6/5/5/5/6/5/6/5，**无节点落在 1–3 区间**，无层级缺失迹象。

**但仍存四处已知的未覆盖区**（非子特性数量问题，是语义盲区）：

1. **多学习者形态**——BOM 未决项已明确「本版单人，架构上账本按人分区即可，不做提前实现」，故**刻意不列入树**。若将来重启，属 L1 全新分支而非现有节点扩充。
2. **语音交互闭环（B0 档）**——org-design 未决项 1 悬置（「纯听/影子跟读如何落盘」）。当前树中 L1-4 仅有「时间档位」覆盖 B0 的时长维度，**落盘机制尚无特性承载**。裁决 B0 方案后须补。
3. **教学法文献核实**——非产品特性，是设计前提的验证任务，不入产品树。
4. **能力维度的粒度本身**（v0.2 新增）——L1-9 假设「6 个能力维度」是正确粒度，但**未经实测验证**。若实测发现维度间高度相关（如「不可直译结构识别」与「句法结构解析」实为同一能力），L1-9 的子特性应合并；若发现某维度实为多个能力的混合体，应拆分。**该粒度是批次 2 的输入契约，冻结后本树方可升版**。

## 五·补、v0.2 新增特性的必要性论证

### 5·补.1 `L1-9 能力建模`（F7/F8 落地）

**为什么必须独立成 L1，而不是散落在其他分支**：v0.1 把难度切成三块放在三个分支（语料供给管难度分带、会话调度管难度反馈、复习调度管语块间隔调度），三者隐含共享同一份「学习者当前水平」状态却无单一归属。这违反两条纪律——

- **特征树卡 B 段「不重复挂接」**：同一子特性只在树上出现一次，按最可能访问的组挂载。三处各自维护一份水平判断，等于同一状态被挂接了三次。
- **kernel §5「状态只能由产物跃迁」**：`learner-state.md` 的「难度档」若可被人工直接设定，它就是配置而非状态；「我现在 L3」是声明不是状态。能力画像必须**从判定记录派生**。

**该分支的不可替代性**：其余八个分支都消费能力画像（语料供给据此编排难度、会话调度据此调整、复习调度据此配比、进度度量据此呈现漂移），但**没有一个分支「拥有」它**。横切状态必须有单一归属，否则派生来源、衰减口径、刷新时机三处各自实现，必然发散。

### 5·补.2 `L1-8 判定难度分布` / `SM6`（F8 落地）

现有 AC 全是二值判据（「判定正确率 ≥ X%」），**没有难度锚**。后果：题目难度一旦随能力上移不足，正确率会因「题变简单」而上升，指标漂亮而能力未涨——死法 D1 打卡化的工程变体。SM6 的作用是**作为 SM1 的证伪指标强制同框呈现**：正确率涨而难度锚不涨时，仪表盘主动打黄灯。

### 6.1 生态图交叉校验的发现：新增 `B0 音频失效降级`

**反查方法**（卡内 E5）：生态图中每个外部系统若「失效后果」无法映射到任何特性，即提示缺特性。

逐系统反查 13 个外部系统后，**TTS 引擎是唯一落空的**：

- TTS 失效的后果是「B0 整档报废」——而 B2/B5/B15 不受影响。
- 但树中 L1-4 会话调度下的「时间档位」只定义了 B0 的**时长与形态**，**没有任何特性负责 B0 在音频不可用时怎么办**。
- 现有树把「B0 落盘机制」已列为已知盲区（§五 盲区 2），但**只覆盖了「B0 如何落盘」，未覆盖「B0 的依赖失效时如何降级」**——这是两个不同的问题。

**建议新增特性**（待批次 9 系统流程裁决后落位）：

```
L1-4 会话调度
  └ 时间档位 →（新增子特性）B0 音频降级策略
```

**降级候选与代价**：B0 退化为「无音频的复现题」时，它从「零交互」变成 B2 的形态——**这是业务决策而非技术决策**，因为它改变了 B0 的定义。⚠️ 登记为 goal-keeper 待决，本轮不擅自定义。

**其余 12 个外部系统反查通过**：云 LLM → L1-3 判定级别分级 ✅；本地模型 → 同上 ✅；用户密钥 → 同上 ✅；账本文件 I/O → L1-6 账本契约 ✅；Keychain/Widget/快捷指令/菜单栏/热键/后台音频 → L1-7 设备形态 + L1-4 唤起入口 ✅；iCloud/Handoff → L1-7 同步层 + 无缝切换 ✅；编辑器/CLI 壳/git/补切脚本 → L1-6 账本导出备份 + L1-1 材料生成 ✅。

**结论**：批次 5 校验发现 **1 处缺特性**，其余维度仍待批次 6/7/8/9。**本树维持草稿状态**——卡内边界明确「不保证完整性，越晚发现缺失越可能破坏项目」。
