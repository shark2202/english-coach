## 一、错题——自我修正闭环（本项目最关键的一张图）

```
                    ┌──────────────────────────────┐
                    │                              │
                    ▼                              │
    ┌───────────────────────┐                      │ 同错二犯
    │      (未修复)          │──同类错误再犯──────────┤
    └───────────┬───────────┘                      │
                │ 首次入本                          │
                ▼                                  │
    ┌───────────────────────┐                      │
    │      (待验证)          │──验证未通过──────────►│
    └───────────┬───────────┘                      │
                │ 验证通过                          │
                ▼                                  │
    ┌───────────────────────┐                      │
    │      (已修复)          │──持续观察─┐          │
    └───────────┬───────────┘           │          │
                ▲                       │          │
                │ 再次验证通过           │          │
                │                       ▼          │
    ┌───────────┴───────┐       ┌──────────────────────────────┐
    │      (复发)         │───────│          (复发)              │
    └───────────────────┘       └──────────────────────────────┘
```

**这张图要回答的唯一问题**：*「学会了」这件事，在系统里是什么形状？*

答案是：**不是一个状态，是一个反复重新达成的状态**。`(已修复)` 永远待在一根回退线上——因为 org-design §6.1 把「错题修复率（同错二犯率）」列为**核心指标**，而任何不允许二犯的状态机，都会让这个指标恒为 100%，从而**作废整个质量度量体系**。

**卡内 B 段警告的实证**：「轻率标无效——标『无』开发会真的阻止它，终态复活常被误杀」。本图的三条 `↩`（未修复↺待验证、已修复↺复发、复发↺已修复）正是被误杀就会致命的三处。

## 二、维度掌握度——升降与衰减

```
                  连续达标上移（样本≥5 且锚位连续2次稳定）
        ┌──────────────────────────────────────────────┐
        │                                              ▼
   ╭────────────╮ 连续达标上移                 ╭────────────╮
   │    (生)     │────────────────────────────►│  (自动化)   │
   ╰────────────╯                             ╰────────────╯
        │      ▲                                   │     ▲
        │      │ 跌破下移                           │     │ 跌破下移
        │      │                              跌破下移   │
        │      │                                   │     │
        ▼      │                                   ▼     │
   ┌───────────────────────┐ 连续达标上移    ┌────────────┐
   │       (半熟)           │───────────────►│            │
   └───────────────────────┘                └────────────┘
        ▲                                             
        └──────────── 跌破下移 ──────────────────────────┘
```

**关键读法**：图中两条 `跌破下移` 虚线（从半熟到生、从自动化到半熟）是**能力会退步**的机制化表达。若把它们删掉——只在向上箭头流动——模型就退化成 v0.1 的「越用越强」，而这在现实中不成立：长时间不练，`(自动化)` 会退回 `(半熟)`，进而退回 `(生)`。

**被刻意禁止的捷径**：(生) →(自动化) 无箭头。卡内 E6「能否跳过某状态」的答案在这里是**不能**——跳过会使掌握度曲线失真，SM5 的轨迹斜率不可解释，而 SM6（判定难度分布）正是靠这条曲线的可信度来证伪 SM1 的。

## 三、练习项——锁、心跳与接管

```
   ◎(待补切)
      │ 补切完成（材料+预嵌细则齐备）
      ▼
  ┌──────────┐
  │  (可取)   │◄──────────────┐
  └────┬─────┘               │
       │ 取用并加锁           │ 心跳超时释放  ↩①
       ▼                     │  ┌────────────┐
  ┌──────────┐               │  │  (锁定)     │
  │  (锁定)   │───────────────┘  └─────┬──────┘
  └────┬─────┘                         │ 消费完成
       │                               ▼
       │                        ┌──────────┐
       │ 水位回收 ↩②             │ (已消费)  │
       └────────────────────────►│          │
                                └────┬─────┘
                                     │ 判定降级复查 ↩③
                                     ▼
                                ┌──────────┐
                                │  (作废)   │◉
                                └──────────┘

   (待补切) ──材料作废──► (作废)
   (可取)   ──材料作废──► (作废)
```

**这张图承载死法 A3 的全部防线**：

| 编号 | 回退 | 失去它会怎样 |
|---|---|---|
| ↩① | 锁定 → 可取 | 设备崩溃/被杀 → 该项**永久**被锁死，队列逐项耗尽 → App 空转 |
| ↩② | 可取 → 待补切 | 队列无法重整，水位线策略失效 |
| ↩③ | 已消费 → 作废 | **本轮新发现**：T0/T1 判定质量塌陷时无重练路径，死法 A9 只能被动承受 |

`↩③` 是上一轮设计里完全不存在的转变。它的来源是 BOM v0.3 新登记的死法 **A9（离线判定质量塌陷）**——既然承认降级判定可能不可信，就必须有一条「作废重做」的路，否则降级只会被记录而不会被纠正。

## 四、能力画像与同步游标——两个退居后台的状态机

### 4.1 能力画像（新鲜度心跳）

```
   ◎(现行) ◄────── 新判定记录到达 ──────┬────── (陈旧)
      │                                  │        ▲
      │ 超 14 天无判定                    │ 超 14 天无判定
      ▼                                  │        │
   ┌──────────┐                          └───►─────┘
   │  (陈旧)   │  ── 陈旧期间材料编排降级为通用兜底包（不按过期画像编排）
   └────┬─────┘
        │ 能力重估 / 策略重定
        ▼
   ┌──────────┐
   │ (已封存)  │◉   ← 全部历史画像保留，为 SM5 的变化轨迹提供数据
   └──────────┘
```

`现行 ⇄ 陈旧` 是一个**自持循环**：它不靠练习推动，而靠「多久没练」推动。这正是 BOM v0.3 的 G4——**画像新鲜度的对手不是判断错误，是时间本身**。

### 4.2 同步游标（同步三态 → 四态）

```
   ◎(单机) ──用户开启同步──► ┌──────────┐
     ▲   ▲                   │ (同步中)  │
     │   │                   └────┬─────┘
     │   │ 用户关闭同步            │ 同步完成
     │   │                   ┌────▼─────┐
     │   └───────────────────┤ (已同步)  │◄──── 下次同步开始 ────┐
     │                       └────┬─────┘                      │
     │                            │ 下次同步失败                │
     │                            ▼                             │
     │                       ┌──────────┐      自动重试 ─────────┤
     └───────────────────────┤(同步失败) │                      │
        用户关闭同步           └──────────┘────────┘             │
                                                        (同步中) ┘
```

**⚠️ 这张图改写了既有设计**：**写本图时**，`app-design.md` §九 A10 的对策写的是「同步状态显式**三态**」。但同步失败时，三态中的任何一态都是**撒谎**：

- 归「同步中」→ 界面永远转圈，学习者以为在同步，其实早已失败；
- 归「单机」→ 失败被掩盖，账本已陈旧却显示「单机模式，功能完整」。

**A10 的对策本质是「不假装新鲜」，而把失败塞进三态恰恰是在假装。** 故本图新增第四态 `同步失败`，并要求批次 4 的决策表补齐「同步失败 → 界面如何呈现」的分支。

⚠️ **现状对齐（2026-10-14）**：`app-design.md` §九 A10 的三态旧措辞**已由编排者改为四态**，与本图新增的第四态一致；`03-data-dictionary.md` v0.2 的 DD703 亦已按同一理由扩为四态（其 §三 挂账 2 已登记，原三态的表述留在该挂账内作为历史）。**本图的论证不因上游改写而失效——它论证的正是「为什么必须扩为四态」。**

```
                      │                                  ▼

                      │                                  │

                      │                      │           │      T2补判 ↩④
                      │                      │           │           │
                      │                      ▼           ▼           ▼
                      │                   ┌────────────────────────────┐
                      │                   │  错题(未修复) ──首次入本──►   │
                      │                   └────────────────────────────┘
                      │                              │
                      │                        验证通过 / 未通过
                      │                              ▼

                      │                                              │
                      │                                          同错二犯 ↩⑤
                      │                                              ▼
                      │                                        错题(复发)
                      │
                      └──► 判定结果 ──► 维度掌握度 升降 ──► 能力画像刷新
                                          │                      │
                                          └──────────────────────┘
                                                 画像持续新鲜
```

**合并视图暴露的一处结构问题**：`(材料)`、`(练习项)`、`(交互轮次)` 三者都在链路上，但**它们的触发事件来源不同**——材料由标注流程驱动、练习项由队列调度驱动、轮次由用户行为驱动。三条驱动线在状态表里是独立的八张表，合并后才发现：**没有任何一张表说明「材料被淘汰时，正在锁定它的练习项怎么办」**。

**已补规则**（见状态表 §一、§五）：材料 → 作废 触发练习项 → 作废。**这是本轮通过合并视图才发现的跨表缺口**——单看任一张表都不觉得有问题。

## 五·补、能力维度正交矩阵——6 个维度 × 3 个熟化等级的落点

> 本节不在卡内状态图要求内，是 goal-keeper 2026-10-14 裁定「词块熟不熟即学会了」之后补产的一张图。**横轴逐字取自 `03-data-dictionary.md` 数据目录「能力维度列表」（6 维，不增删不改名），纵轴取自「语块熟化等级列表」（生 / 半熟 / 自动化）。** 格内是「该维度上由哪个标注类型承载」（`DD403` 标注类型列表），左侧是该行用的练习形态（`DD303` 练习形态列表）。

```
               ┌────────────────┬────────────────┬────────────────┬────────────────┬────────────────┬────────────────┐
               │ 术语识别       │ 句法结构解析   │ 不可直译       │ 论证结构还原   │ 语域文体识别   │ 立场情态判读   │
               │                │                │ 结构识别       │                │                │                │
               ├────────────────┼────────────────┼────────────────┼────────────────┼────────────────┼────────────────┤
自动化* 循环   │ 术语陷阱       │ 限定嵌套       │ 走不通 A       │ 走不通 B       │ 语域标记       │ 情态立场       │
 ▲上移  ▼回落  ├────────────────┼────────────────┼────────────────┼────────────────┼────────────────┼────────────────┤
半熟*   复现   │ 术语陷阱       │ 限定嵌套       │ 名词化链       │ 无载体         │ 语域标记       │ 情态立场       │
 ▲上移  ▼回落  ├────────────────┼────────────────┼────────────────┼────────────────┼────────────────┼────────────────┤
生*     输入   │ 术语陷阱       │ 限定嵌套       │ 名词化链       │ 无载体         │ 语域标记       │ 情态立场       │
               └────────────────┴────────────────┴────────────────┴────────────────┴────────────────┴────────────────┘
```

**横轴取值（逐字，与 `03` 数据目录「能力维度列表」一致，图中第 3 列因列宽折为两行显示）**：术语识别 / 句法结构解析 / 不可直译结构识别 / 论证结构还原 / 语域文体识别 / 立场情态判读

**纵轴取值（逐字，「语块熟化等级列表」）**：生 / 半熟 / 自动化

**图例**：`▲上移` = 连续达标上移（样本 ≥5 且难度锚在当前档连续 2 次稳定）；`▼回落` = 跌破下移（最近 N 次判定加权正确率跌出当前档下界）。两条条件与 `04-state-table.md` §三同源，**事件表归 `04` 所有，本图只画落点、不重复它**。行的判定对象（`DD202`）：生 / 半熟两行为理解结构，自动化行为输出文本。

**图中没有跨行的斜箭头——「生 → 自动化」无捷径是被刻意保留的**（`04` §三：跳过会使掌握度曲线失真、SM5 的轨迹斜率不可解释）。

**A ——「不可直译结构识别 × 自动化」走不通。** 三条理由，条条有出处：

1. **载体可缺**：`03` §1.4 明写「只有 DD406 时，学习者能识别结构但仍会在阅读中自动套中文——**那正是 P1 问题本身**」。要走到自动化，DD406（结构含义）与 DD407（中文化说法，记录失败路径）须同时在场，而 **DD407 的必填为「否」**——可以缺，缺了系统不会拦。
2. **应用侧载体缺位**：F4 回译对照视图（英文原文 / AI 参考译文 / 不可直译标注并置）在特性树中零需求承接（`01` §五 盲区 4），其落位已作为 M1 登记在 `15` §八 待 goal-keeper 决。训练侧再扎实，也没有「并置对照」这一侧接住它。
3. **度量只到「能指出」**：SM2 度量的是「遇标注结构能否指出其存在与含义」，并自陈其假设为「能指出」可迁移到「真实阅读中能察觉」。**自动化要的正是后者**，而后者当前没有任何直接指标。

所以这一格**留空并标出走不通，而不是画满**：半熟可达（有标注可指出、有 SM2 可测），自动化要同时跨过「练得出、用不上、测不到」三道缺口。**画满了才是不诚实的。**

**B ——「论证结构还原 × 自动化」走不通。** 理由是粒度不匹配，不是这一维不重要：

- **粒度不匹配**：语块 = 搭配 / 短语 / 句式 / 习语等 **2–6 词**的自然共现单位（org-design §5.1），而「语块熟化派生」要求**每个语块独立计算、不跨语块汇总**（`03` §2.2）。论证关系是跨句段的，一次判定的成败无法归因到某一个 2–6 词的语块上——归因就意味着汇总，汇总即违反派生式。
- **没有可织入的语块**：`DD403` 的五类标注（名词化链 / 限定嵌套 / 情态立场 / 术语陷阱 / 语域标记）没有一类承载论证链，而 `DD309` 织入语块要求语块落在某条标注的原文片段上（`DD404` / `DD405` 的起止字符锚定）。
- **有判定、无比照**：SM1 度量「论证结构题正确比例」，但那是**材料级**指标，反推不出某个语块的熟化等级。

故该列生 / 半熟两格标 `无载体`：只能靠输入 · 理解结构的判定记录计熟化，**没有可被复现织入的语块**，也就没有从半熟继续上推的抓手。

**C —— 回落通道（`▼回落`）**：`自动化 → 半熟 → 生` 的回落与 §二 同源，落到语块一级由 **DD802 熟化轨迹**承载（负斜率不得被平滑掉）。⚠️ **但语块级回落目前没有出口**：`DD609` 衰减标记与 SM5 都挂在**维度掌握度**（`DD608`）一侧；org-design §6.1 收敛层虽有「语块账本规模与熟化分布（生:半熟:自动化）」，但那是**当期分布**——一个语块从自动化掉回半熟，分布比例动了，没人知道**是它掉的**。负斜率记下来了，看不见——列为待裁定 T3。

**读法说明**：

- **回答**：同一个词块在 6 个能力维度上分别靠什么形态推进（格内 = 承载它的标注类型）、推到哪一格会被什么挡住（走不通 A / B）、以及退回时从哪一格掉下来。
- **不回答**：① 六个维度各该记多少分——那是 `DD603` / `DD604` 的事，且 6 维粒度本身尚未冻结（BOM 未决项 6；`01` §五 盲区 5）；② 上移 / 下移的触发事件表——属 `04-state-table.md`（掌握度 §三、语块 §三b），本图只画落点；③ 任何单个语块的实际进度——这是结构图不是数据图；④ **不含 B0 档**：B0 落一行 `DD107=0` 的 journal 行、不产判定（`03` §1.1 与 §四挂账 3），故 B0 不推进任何一格，图中形态均属 B2 / B5 / B15。

**待裁定（本节列出，不混进图里当已定设计）**：
