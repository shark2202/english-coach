## 零、本卡的口径适配（明示，不静默套用）

卡内 B 段有一条硬边界：**「不要为所有屏幕变形建独立框——同一屏幕因用户类型略有不同，应在 DAR 中记录差异，UI Flow 只保留一个屏幕框，除非系统状态导致屏幕有显著变化。」**

本项目的 `app-design.md` §五 与死法 **A8（桌面/移动体验互相污染）** 要求的是另一种分型：**iOS 单列会话流与 macOS 三栏是两套独立布局，不是同一布局的两种宽度**。二者的操作面（拇指可达 vs 键盘优先）、信息密度、排版规则都不同。

**处理方式（明示偏离）**：

| 判据 | 卡内原文 | 本项目处置 |
|---|---|---|
| 差异是否显著 | 「略有不同」（如管理员多一个链接） | iOS 与 macOS 的会话屏在栏数、排版、输入方式上均不同，属**显著差异** |
| 差异的成因 | 「用户类型」 | 「设备形态」——死法 A8 明确禁止用响应式拉伸消解 |
| 分型粒度 | 一个屏幕框 | 保留一个**规范屏幕名**，在两张分型子图中各画一个框，DAR 按同一规范名分节 |

**偏离的代价（自陈）**：屏幕框数（18）大于规范屏幕数（13），图读者需要多一次名称映射。**收益**：壳层实现不会把 iPhone 布局拉伸到 Mac，这是 A8 唯一可验证的防线。若评审判定偏离不可接受，回退方式是合并为单套布局——**那将直接复现 A8**。

**另一处口径**：「系统标准屏幕（如全局帮助菜单）」按卡内 E1 排除。本项目无帮助菜单；但**「状态与设置」保留**——它承载 DD703 四态与判定级别，是死法 A10 与 A9 的对策落点，不是标准屏幕。

## 一、E1 屏幕范围（哪些进图、哪些不进图）

### 1.1 纳入判据

| 判据 | 本项目命中 |
|---|---|
| 高价值任务（复杂导航路径、经常执行、最重要） | 唤起与开练、会话、判定反馈、错题本、状态与设置 |
| 需要复杂逻辑决定跳转的屏幕 | 首启引导（冷启动自举 6 条分支）、队列空提示（5 条降级分支） |
| 死法对策的界面落点 | 判定反馈（A9）、状态与设置（A10）、队列空提示（A3） |

### 1.2 排除与「不单独建框」

| 不进图的东西 | 理由 | 去处 |
|---|---|---|
| TTS 不可用 / ASR 不可用 / Keychain 失效 等**集成错误屏** | 卡内 E1 明文「排除错误屏幕」 | [DAR 13](13-display-action-response.md) 的显示前提条件 |
| 离线 / 队列空 / 陈旧读 等**提示条** | 是 S5 的局部形态，不是独立屏 | S5 的显示前提条件 |
| 菜单栏下拉、全局热键、Widget、快捷指令 | 平台唤起入口，不承载内容跳转 | 作为进入 M1 / I6 的**入边源**标注 |
| TTS 失效时 B0 档如何降级 | **业务决策未裁决**（特性树 §六 6.1、生态图 §4.2），无内容可画 | 挂账，见 §六 |

> **屏数守则自检**：规范屏幕 13 个 > 7+2=9 上限 → **分设备分型、分层出 4 张子图**（下节），子图框数为 **6 / 7 / 4 / 7**（口径见 §九 9.1）。上界全部满足（最大 7 ≤ 9）；**子图 C 为 4 框，低于 7±2 带的下界 5**——7±2 是认知负荷的**上界**警戒（Miller 带），4 框不构成过载，故本图不改，登记为 §十 挂账 6 待 goal-keeper 定夺。**18 个屏幕框 − 13 个规范屏幕 = 5 套双形态布局**（S2/S3/S4/S9/S11——⚠️ 此前此式误写为「= 4」，且漏列 S9）。⚠️ **该差值目前无法逐屏核实**：全仓缺少一张「规范屏幕 ↔ 屏幕框」的映射表，`13-display-action-response.md` §1.2 只给了 macOS 侧的合并规则（如 S7+S8=M6、S10+S9=M7），iOS 侧无对应表。**映射表缺失已登记为 §十 挂账 7**——在补上之前，「18−13=5」只说明差值，不构成双形态清单的证明。

## 八、挂账收口（三项）

### 8.1 挂账一：同步四态在导航上的落位

**结论：四态全部落在 S11「状态与设置」的常驻状态行上，不新增任何屏幕。**

这是本轮的一项设计判断：**同步失败不是一屏，是一行字**。若为它单独建「同步失败屏」，则失败发生时学习者被迫跳转才能知道账本已陈旧——而陈旧读的伤害发生在**他没跳转的那段时间**（决策树 §三「不可生成」分支）。因此四态采用**常显状态行 + 详情页下钻**两级：

| 层级 | 位置 | 承载内容 | 可见时机 |
|---|---|---|---|
| 一级（常显） | 全部 18 个屏幕框的状态行槽位 | DD703 四态 + DD704 同步至时刻 + DD705 来源设备 | 始终，无需任何操作 |
| 二级（下钻） | S11 状态与设置 / M8 | 失败原因分类、冲突裁决清单、BYOK 可用性 | 学习者主动进入 |

四个失败分支（`07-decision-tree.md` §四）的**导航落点**：

| 失败分支 | 一级状态行文案（常显） | 二级落点 | 是否阻断开练 |
|---|---|---|---|
| 本地存储不足 | `⚠ 同步暂停 · 存储不足 · 账本停留在 14:20（iPhone）` | S11 → 系统设置清理指引 | **否**（账本仍可读写） |
| 云服务未登录 | `⊘ 已转入单机模式 · 云服务未登录 · 账本停留在 14:20（iPhone）` | S11 → 登录引导 | **否** |
| 存在未解冲突 | `⚠ 同步挂起 · N 项待裁决 · 账本停留在 14:20（iPhone）` | S11 → 冲突裁决清单（S7 区） | **否** |
| 原因不可判定 | `⚠ 同步失败 · 账本停留在 14:20（iPhone）` | S11 → 立即重试 | **否** |

**两条纪律的落点说明**：

1. **界面不得隐藏同步状态**——一级状态行是**全局常驻元素**，不是某一屏的属性。`I2/I3/I5/I7/I10` 与 `M1..M8` 全部带同一槽位。DAR 的 `ELMT-GL1` 是本模型中**唯一一张跨屏元素表**。
2. **云服务未登录必须明确告知已转入单机模式**——该分支文案以「**已转入单机模式**」开头并使用 `⊘` 而非 `⚠`，因为它与另三个分支性质不同：另三个是「同步坏了」，它是「同步已关、单机在工作」。静默降级正是决策树 §四点名禁止的行为。

**「自动重试不提升状态」在导航上的体现**：I5 与 M5 的「立即重试」动作**留在原屏**（不跳转），因为状态表 §八 要求失败态必须由一次成功同步才能离开——重试动作不应产生「看起来有进展」的界面迁移。

### 8.2 挂账二：判定级别 T0/T1/T2 的降级标记如何可见

**约束**：`kernel.md` §6「全程仅三触点 + 默认零推送」。判定降级标记**不得**新增触点。

**方案：状态行双槽常显 + 随行词标 + 仪表盘分层，三者全为数据驱动的显示，不产生任何一次额外出场。**

| 载体 | 位置 | 显示规则 | 新增触点 |
|---|---|---|---|
| 状态行右槽 | 全部 18 框 | `判定 T0` / `判定 T1` / `判定 T2`；当待复核计数 > 0 时追加 `· 待复核 N` 并转警示色 | **0** |
| 随行词标 | S4 / M3 每条反馈旁 | `预嵌` / `本地` / `联网`（DD204/DD109 的中文前缀） | **0**（随轮次自然出现，不单独出现） |
| 分层统计 | S10 / M7 | SM6 判定难度分布卡 + 降级占比；SM6 打黄灯时给出去向 `⟨SM6 打黄灯 → 查判定级别配比⟩` | **0**（用户自行打开仪表盘） |

**明确不做**（防止后续实现者「补全」成打扰）：

- ❌ 弹窗 / 模态 / 遮罩
- ❌ 本地通知 / 推送（A4 默认零推送是产品政策）
- ❌ 红点徽标 / 角标计数
- ❌ 声音 / 震动

**为什么这满足「降级必须让学习者先看见」**：`kernel.md` §6 保护的是「学习者出场的时刻数」，而非「学习者能看到的信息量」。常显状态行不产生出场——学习者练的时候它就在那里，练完看仪表盘时它在第二个槽位。**A9 的伤害是「无人察觉」，不是「无人被打扰」**；本方案治前者而不动后者。

**T2 补判完成后**：S4 的随行词标由 `预嵌` 自动变为 `联网`，状态行右槽同步切换。**变化是就地更新，不是通知**。

### 8.3 挂账三：iOS 与 macOS 各自独立的屏幕清单

**已在 §二 与 §三–§六 收口**，此处只留三句结论：

1. **iOS 侧 10 框**：I1–I10，单列会话流，底部档位条，拇指可达。
2. **macOS 侧 8 框**：M1–M8，三栏容器，衬线排版 + 行宽约束，键盘优先。
3. **两套清单不共享布局，只共享 4 个规范屏幕名**（S2 唤起与开练 / S3 会话 / S4 判定反馈 / S11 状态与设置）。**实现期若发现某框在三栏里被拉伸成单列的样子，视为 A8 复现。**
