### 4. 明示偏离一：处理流程三列并为一列

卡内 I 段说矩阵「通常**至少 5 列**——前 3 列分别是 L1/L2/L3 处理流程步骤」。本轮**尚无任何流程步骤**，三列取同一值 `⏳7` 无信息增量，故并为**一列**「处理流程步骤（L1/L2/L3）」。**批次 7 回填时须拆回三列**，且按卡内 E1 要求：L1 名称复制到其下每一行、L2 复制到其下每一行、**决策框视为流程步骤**、一个步骤对应多个需求时重复该步骤行。

## 一、矩阵列定义与标注约定

| 列 | 内容 | 本轮取值 |
|---|---|---|
| REQ | 需求唯一标识符（卡内完成标准第 1 条：每个需求有唯一 ID） | REQ-001 … REQ-084 |
| 需求陈述 | 一句话可判定为「系统须…」的行为陈述 | — |
| 特性 | L1 / L2，取自[特性树](01-feature-tree.md)；**一个需求可挂多个特性**（卡内 E2：「一个需求映射多个流程步骤时复制需求行」，此处同理） | 49 个 L2 全覆盖 |
| G | 追溯到的 BOM 业务目标 G0–G4（卡内 E2 有用映射之一：业务目标→特性→需求） | 每需求 ≥1 |
| BR | 业务规则 + **来源定位**。卡内 E3 四法之末（「每规则占一行」）：本表每个需求行只放**一条主规则**，其余关联规则在 §六·附表按 BR 编号反查 | BR-001 … BR-084 |
| 流程 | 处理流程步骤（L1/L2/L3） | ⏳7 = 待批次 7 回填 |
| 用例 | 关联用例 | ⏳7 = 待批次 7 回填 |

**BR 编号约定**：BR 编号与所在行的 REQ 编号**同号**（BR-0NN ↔ REQ-0NN），是本表为便于回查而设的**指针**，不是规则的新定义——每条 BR 的权威陈述在其来源文档，来源已逐条内联在 BR 单元格内。**规则不重复维护**。

### 4.3 缺特性发现：BOM 的 F4 无任何特性承载（本轮最重要产出）

**反查方法**（卡内 E5）：把 BOM 的每个产品概念 F1–F8 拿到 RMM 上反查「哪些需求实现了它」。F4 落空。

| 项 | 内容 |
|---|---|
| **F4 的定义**（BOM §三） | 「回译对照视图（**可选**）：并置英文原文 / AI 参考译文 / 不可直译标注；不追求唯一译文，暴露『此处多译/不可译』」 |
| **反查结果** | **84 条需求中，零条实现 F4** |
| **为什么不是「已实现，只是没标 F」** | F4 的三个要素在需求层逐个缺席：①「并置」——无任何需求规定某一界面须同时呈现英文原文、AI 参考译文与结构标注；②「AI 参考译文」——F4 的译文是**参考译文**，与 REQ-023 的输出判定参考答案、REQ-024 的错题本参考答案都不是同一物（那是判定侧的产物，不是阅读侧的对照物），无需求产生阅读侧参考译文；③「暴露多译/不可译」——REQ-014 规定了术语首选译法**有且仅有一个**，REQ-015 记录了历史变体，但没有任何需求把变体**呈现**给学习者 |
| **更广的缺口** | 特性树 9 个 L1 中**无一承载「学习者读材料并看到对照」这一交互面**——L1-2 承载的是标注的**生产**（谁生成、谁质检、落哪），不是标注的**呈现**；L1-8 承载的是度量不是阅读界面 |
| **候选落位（不擅自定义，须 goal-keeper 裁决）** | ① 新增 L1-10「输入呈现」（会突破特性树「顶级 L1 ≤7±2、已达 9 上限」的自检纪律，须先拆分）；② 挂 L1-2 新增 L2「标注呈现 / 对照视图」（不增 L1，守住上限，但会让 L1-2 变 7 个子特性，仍在 ≤7±2 内） |
| **代价明示** | F4 在 BOM 中标为「可选」。**但它标「可选」的理由是「不追求唯一译文」，不是「可不做」**——若不实现，学习者仍只能看到单一中文说法，P1「大脑自动套中文结构」的问题在阅读侧无对策。⚠️ 这是本轮最需要裁决的一项 |

> **与批次 5 发现的区别**：批次 5 的缺特性（TTS 失效降级）是**系统集成侧**的缺口，需求已在 BOM F1 与特性树 L1-4 中隐含存在；本轮的 F4 是**产品概念侧**的缺口——BOM 明确写了它，但特性树与需求层都没有承接它。**两者不同源，不重复计数。**

| L1-8 | 不可直译识别率 | REQ-069 | 同上，无记录手段需求 |
| L1-8 | 查证收敛率 | REQ-070 | 同上；且 SM3 的假设已明示「学习者回避记录则失真」，而**无需求处理该回避** |

| L1-8 | 能力漂移可见 | REQ-073 | 轨迹的**采样与刷新频率**无需求 |
| L1-9 | 遗忘衰减检测 | REQ-082 | ⚠️ 「连续 N 次」的 N 未定义（数据字典同样挂账），需求不可验收 |

**两条结构性结论**：

1. **L1-8 进度度量是 6 个 L2 中 5 个单需求支撑的唯一分支**——密度 1.17 全树最低，且全部是「呈现」类需求。**度量不能没有记录手段**：本轮在 L1-8 发现的不是需求太少，而是**需求的类型单一**（只有呈现、没有采集）。
2. **单需求支撑不等于缺需求**：24 个中有 9 个的唯一需求本身是**待裁决项**（REQ-009/016/025/055/071/082/083/084 等），它们要到裁决完成后才会细化。批次 7 回填用例时，这批条目应优先补第二需求。
