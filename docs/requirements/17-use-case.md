## 零、口径与模板约定

### 0.1 三条编写纪律（卡内 B 段粒度红线）

| 纪律 | 含义 | 本文件的执行方式 |
|---|---|---|
| **触发原因必须是系统可检测的实际动作** | 「用户想继续学习」是意图，系统检测不到 | 触发原因一律写可检测事件：发出 `继续` 文本 / 点击续学入口 / 说出 `停`。**意图写进描述字段** |

## 一、UC-01 继续未完成的会话

| 字段 | 内容 |
|---|---|
| **名称** | 继续未完成的会话 |
| **ID** | UC-01 |
| **描述** | 学习者希望从上次中断的位置接着练，不重新选材、不重述上次到哪——他要省掉的是**启动成本**，不是学习内容。这是使用频率最高的路径。 |
| **演员** | 学习者 |
| **组织受益** | 直接关联 **G0**（读完 2000 词总耗时 60–90min → ≤45min）：启动成本是碎片时间场景下 G0 的第一项损耗。SM4（没打开译文读完的天数）依赖本路径的可达性 |
| **使用频率** | 全部唤起中的多数路径（默认档，默认 B5） |
| **触发原因** | 学习者发出 `继续`，或点击续学入口——**系统可检测的文本匹配或入口点击** |
| **前提条件** | ① journal 尾行可定位到一条未完成会话的落盘轮；**或** ② 无续学点但 learner-state 中目标锚已锁定且预切队列非空。两者满足其一即可 |
| **后续条件** | ① 会话状态 = 进行中；② 练习项已被本次会话消费锁锁定；③ 续学点已呈现并标注来源设备与最后同步时刻；④ **默认档为 B5**，除非 learner-state 记录了未完成的指定档会话（此时续该档） |

- **主要路径**（7 步 · 用户动作与系统响应交替）
  1. 学习者发出 `继续`。
  2. 系统按决策树 §一 执行冷启动自举，读取缓存与 journal 尾行，判定存在续学点。
  3. 系统呈现续学点，并标注其来源设备与最后同步时刻（**陈旧读可见**，死法 A10）。
  4. 学习者确认继续。
  5. 系统取出该续学点对应的练习项并置消费锁，呈现本轮材料。
  6. 系统在每轮结束时向 journal 追加一行（微落盘）。
  7. 系统按档位预算继续开练或转入 UC-08 收尾。
- **替代路径**
  - **AC1**｜调用条件：缓存尾部与 journal 尾行不一致。→ 系统以 journal 尾行为准重建缓存 → 回到步骤 5。（方向不可反：账本是唯一事实源）
  - **AC2**｜调用条件：同步状态为「同步中」或「同步失败」。→ 系统如实标注同步时点与来源设备，继续单机开练 → 步骤 5。**不因同步失效阻断任何一步。**
  - **AC3**｜调用条件：journal 中无可定位的续学点（首练场景）。→ 系统按 learner-state 的档位取队首项 → 步骤 5。
  - **AC4**｜调用条件：续学点所属练习项已被另一设备持锁。→ 系统按状态表 §一 复活路径① 等待心跳超时释放，或提示改取该项 → 步骤 5（AC4 是本用例与 AC10 消费锁接管的接口）。
- **异常情况**
  - **EX1**｜条件：学习者在步骤 4 之前改主意，发出 `停`。→ 转 **UC-06**。
  - **EX2**｜条件：journal 不可读且缓存也缺失。→ 系统不呈现任何续学点，明确告知「账本不可读，无法确认进度」并停止开练。**后续条件 1–3 不满足，但系统不伪造进度。**
  - **EX3**｜条件：预切队列无可取项。→ 系统转入决策树 §三 队列取用与降级链；若兜底包亦不存在，登记补切并以「队列空」结束，会话状态 = 已中断。

> **AC2 与 AC4 两条替代路径是死法 A10 与 A3 的对策在用例层的兑现**：A10 要求「不假装新鲜」，故步骤 3 必须标注来源设备与时刻；A3 要求「不空转」，故 EX3 必须登记补切而非静默等待。

## 二、UC-02 按指定时间档开练

| 字段 | 内容 |
|---|---|
| **名称** | 按指定时间档开练 |
| **ID** | UC-02 |
| **描述** | 学习者手上有明确的碎片窗口（排队两分钟、等车五分钟、午休十五分钟），他用一条口语指令指定本次会话的时间预算，系统据此取用**预切好的**该档任务包。**取包不现场生成、不问问题**——碎片时间的敌人是启动成本。 |
| **演员** | 学习者 |
| **组织受益** | 直接关联 **G0** 与 **G1**：时间预算是 G0 的切片单位；预切包让「查证时间」（G1 的 40–60%）不因启动而膨胀 |
| **使用频率** | 唤起中约三成（按场景分布：排队/等车/午休） |
| **触发原因** | 学习者发出 `2分钟` / `5分钟` / `15分钟` 之一——**系统可检测的档位关键词** |
| **前提条件** | ① 指定档位的预切队列中存在至少 1 个状态为「可取」的练习项；**或** ② 该档位队列为空但本地兜底包存在。**判定级别由 DT-1 在系统内选定，不作为前提暴露给学习者** |
| **后续条件** | ① 档位被记为本次会话预算（DD105）；② 练习项消费完成或会话以 Safe Halt 结束；③ 若队列水位低于水位线，已登记后台补切任务；④ 消耗档内时间不超出所选预算（超出即触发收尾） |

- **主要路径**（8 步 · 用户动作与系统响应交替）
  1. 学习者发出档位指令（如 `5分钟`）。
  2. 系统按决策树 §三 判定该档位队列水位，取队首项并加消费锁。
  3. 系统呈现该档位任务包的第一个轮次。
  4. 学习者作答。
  5. 系统微落盘并呈现下一轮。
  6. 学习者作答。
  7. 系统微落盘。
  8. 系统在档位预算用尽时停止发新轮，转入 UC-08 收尾。
- **替代路径**
  - **AC1**｜调用条件：该档位队列水位为 1（不足 2 的水位线）。→ 系统取该项开练并登记补切任务 → 步骤 3。**补切是后台动作，永不阻塞唤起。**
  - **AC2**｜调用条件：该档位队列为空但兜底包存在。→ 系统取兜底包并登记补切 → 步骤 3。
  - **AC3**｜调用条件：设备 A 持有消费锁且心跳超时。→ 系统在设备 B 接管同一队列项 → 步骤 3（**AC10 消费锁接管的用例落点**；合账零损坏）。
  - **AC4**｜调用条件：设备完全离线且无兜底包，但该档位有可离线内容。→ 系统按档位降一级取用（如 `15分钟` → `5分钟`）并明确告知已降级 → 步骤 3。**降级必须被说出**，不得静默替换。
  - **AC5**｜调用条件：网络不可用。→ 系统从本地队列开练，判定按 T0/T1 执行并标记「离线待判」→ 步骤 3（**AC4 断网可练的用例落点**；恢复后由 UC-07 补判）。
- **异常情况**
  - **EX1**｜条件：学习者发现取到的内容不合适。→ 系统依 `太难了` / `太简单了` 分别转 **UC-04** / **UC-05**。
  - **EX2**｜条件：微落盘写入失败。→ 系统**当轮标为未落盘**，后续条件 2 不成立；已落盘的更早轮次保留。系统须在收尾时显式报告「本次有 N 轮未落盘」，不得静默丢弃。
  - **EX3**｜条件：指定档位的队列与兜底包同时为空。→ 系统给出「队列空且离线/在线」提示并登记补切，会话状态 = 已中断，等下次唤起（**决策树 §三 的空转分支，不重试**）。

## 三、UC-03 只要听（B0 纯听会话）——0 轮会话如何构成完整用例

| 字段 | 内容 |
|---|---|
| **名称** | 只要听 |
| **ID** | UC-03 |
| **描述** | 学习者在做饭、走路、通勤时只想让材料在耳边过一遍，不想回答任何问题。他要的是**语感浸泡**——不可直译结构在无压力语境下的裸听暴露。这是四档里唯一**零交互**的一档。 |
| **演员** | 学习者 |
| **组织受益** | 关联 **G2 / G3**：被动暴露不可直译结构（限定嵌套、情态标记、名词化链）而不进入问答负荷，与 SM2（不可直译结构识别率）构成低压力的输入端 |
| **使用频率** | 高频短次——碎片场景最密集的一档，可一天多次 |
| **触发原因** | 学习者发出 `只要听`——**系统可检测的关键词** |
| **前提条件** | ① B0 档预切队列中存在至少 1 个**已预生成并缓存音频**的练习项（DD308 音频引用必填）；**或** ② 无缓存音频但本地 TTS 可用 |
| **后续条件** | ① journal 中存在且仅存在**一行** `DD107 轮次序号 = 0` 的 B0 会话记录；② 会话状态 = 已完成；③ **下一步指针不推进**（B0 不消费难度锚）；④ **不产生任何判定**，故不写错题本、不触发掌握度升降；⑤ 本次听过的材料计入输入量统计 |

### 3.1 「0 轮会话」为什么仍是一个完整用例

这是本批次必须收口的问题之一，答案有三层：

| 疑问 | 回答 |
|---|---|
| **它的「动作」是什么？** | 动作是**会话级的播放会话**，不是问答对。学习者的动作为「唤起 + 开始播放」共 2 次，**此后与材料之间的交互动作数为 0**。被交互的不是人，是播放进程 |
| **怎么判定完成？** | 完成判定**不依赖交互轮次**，依赖两条可机器检测的退出条件：① **退出条件命中**——播放自然结束 / 学习者说 `停` / 达到 30 分钟上限（AC6）；② **会话级落盘行已写入** journal。两者同时满足即视为用例完成 |
| **0 轮会不会击穿流程完整性？** | 不会。流程完整性要求的是「每条路径到达终止状态、无悬空步骤」，不是「每条路径至少有一个交互轮次」。B0 路径有触发器、有分支点（1.4 的档位分支）、有终止状态，结构完整——见 `16-process-flow.md` §六 |

**关键区分**：「轮次」是 `交互轮次` 对象的基数**下界**（BDD 关系 2.1 的 `0..n`，其业务规则明写「**0 必须允许**」），不是流程实例完整性的条件。**把「0 轮」理解成「模型没覆盖到」是错的——它恰恰是被 BDD 关系 2.1 刻意保住的合法取值。**

### 3.2 落盘形态（本用例对数据字典的分析师裁决）

B0 的落盘不是「悬空」，而是**一行序号为 0 的 journal 行**——这是 `03-data-dictionary.md:46`（DD107）已经写下的取值约定，本用例只是把它补成完整路径：

| 字段 | B0 补记行的取值 | 理由 |
|---|---|---|
| DD104 会话 ID | 指向本次 B0 会话 | 会话存在，只是无交互轮次 |
| DD105 档位 | B0 | — |
| DD107 轮次序号 | **0** | 数据字典已明载「表示无交互轮」 |
| DD106 练习项引用 | 指向本次消费的 B0 练习项 | B0 会话**确实消费了队列项**，故不悬空 |
| **DD108 判定引用** | **空** | 见下方裁决 |
| **DD109 判定级别** | **空** | 同上 |

**⚠️ 分析师裁决（待 goal-keeper 确认）**：BDD 关系 2.3 写「每轮产生恰 1 条判定」，其表注已挂「**待 B0 落盘方案裁决后复核**」。本用例的裁决是——**DD107 = 0 的行不是 `交互轮次` 实例**（数据字典对它的定义就是「无交互轮」），故关系 2.3 的 1:1 约束**不适用于该行**，B0 会话不产判定。

**该裁决的代价（必须说清）**：B0 因此**不产生任何学习效果度量**。若学习者只听不说，SM1/SM2 在该次会话上无数据点，能力画像不因 B0 前进。**这是有意的**——死法 A13（判定假性达标）的对策是不许没有难度锚的判定进入统计，而 B0 连判定都没有，**宁可不度量，不度量假指标**。

### 3.3 主要路径

- **主要路径**（7 步 · 步骤 4 起的学习者动作为 0）
  1. 学习者发出 `只要听`。
  2. 系统取 B0 档队列中带缓存音频的练习项并加消费锁。
  3. 系统开始后台播放，并使播放受锁屏/控制中心控制。
  4. 系统持续播放材料；**学习者在此期间不与材料交互（本用例的交互轮数为 0）**。
  5. 学习者结束本次聆听——播放自然结束、说 `停`，或达到 30 分钟上限（三者任一）。
  6. 系统向 journal 追加**一行** `DD107 = 0` 的 B0 会话记录（DD108/DD109 留空）。
  7. 系统执行会话收尾：不推进下一步指针、不触发复现信号，会话状态转为已完成。
- **替代路径**
  - **AC1**｜调用条件：所取练习项没有缓存音频（DD308 为空）。→ 系统用本地 TTS 生成后播放 → 回到步骤 3，并登记预生成任务。**若本地 TTS 不可用** → 转 AC2。
  - **AC2**｜调用条件：既无缓存音频又无本地 TTS。→ 系统取同档位中**有音频**的下一项 → 步骤 3；若该档无任何带音频项 → 转 EX2。
  - **AC3**｜调用条件：完全离线。→ 播放仅用已缓存音频，**功能不降级**（AC8 纯单机基线）→ 步骤 3。
  - **AC4**｜调用条件：影子跟读已启用（Phase 2 的 ASR 能力）。→ 系统采集跟读音频供后续分析，**本轮仍不产交互轮次、不产判定** → 步骤 4。
- **异常情况**
  - **EX1**｜条件：播放被来电/耳机拔出中断。→ 系统暂停并保留播放位置，学习者可恢复；若学习者选择结束 → 步骤 5（**此时会话按 Safe Halt 语义记账，指针不推进**）。
  - **EX2**｜条件：B0 档队列与兜底包均无可用音频项。→ 系统提示「B0 暂无可听内容」并登记补切，会话状态 = 已中断。**不静默转成 B2 档**——学习者明确说了「只要听」，替他改成问答是违背意图的。
  - **EX3**｜条件：步骤 6 的落盘失败。→ 系统**不把本次标记为已听**（后续条件 1 不成立），并显式告知「本次聆听未记账」。理由与 UC-02 的 EX2 同源：**进度只认账本，账本没写就是没发生**。

## 四、UC-04 反馈「太难了」并即时降档

| 字段 | 内容 |
|---|---|
| **名称** | 反馈「太难了」并即时降档 |
| **ID** | UC-04 |
| **描述** | 学习者在练习中判定当前材料超出能力。他要的是**立刻换材料**，不是「等周度再说」——等到下周再降档，这一周的练习全是浪费。 |
| **演员** | 学习者 |
| **组织受益** | 关联 **G3**（限定/情态误读 ≤1 次/篇）与 **G4**：难度失配是死法 D2 的入口，即时反馈是把「弃用」拦在发生之前 |
| **使用频率** | 中——每档会话内 0–2 次 |
| **触发原因** | 学习者发出 `太难了`——**系统可检测的关键词** |
| **前提条件** | 当前会话状态 = 进行中，且**当前档位不是 B0**（B0 为纯听，不存在难度反馈） |

- **主要路径**（7 步）
  1. 学习者发出 `太难了`。
  2. 系统记录一条难度反馈，关联当前练习项与档位。
  3. 系统按决策表中的难度锚动作提议降一档。
  4. 系统取出降档后档位的下一项练习并加消费锁。
  5. 系统呈现新档位的下一轮。
  6. 学习者作答。
  7. 系统微落盘；剩余轮次继续按新档位供给；若时间预算已尽则转 UC-08 收尾。
- **替代路径**
  - **AC1**｜调用条件：反馈发生在**当前轮的中间**（轮未结束）。→ 系统在**下一轮开始前**生效降档，当轮继续至完成 → 回到步骤 6。**当轮不因难度反馈而作废——作废是 `停` 的专属语义。**
  - **AC2**｜调用条件：降档后的档位队列为空。→ 系统走决策树 §三 降级链取兜底包 → 步骤 5，并登记补切。
  - **AC3**｜调用条件：学习者连续两次在同一会话内说 `太难了`。→ 系统合并为一次降档动作（防止抖动），并在后续条件 1 中记为「重复反馈」，供周度触点 T2 参考。
- **异常情况**
  - **EX1**｜条件：学习者在 B0 会话中说 `太难了`。→ 系统不执行降档（前提不满足），但**记录该反馈**用于下次 B2/B5 选材；B0 不消费难度锚，故不改变任何状态。
  - **EX2**｜条件：档位已是最低档（B0 之上无可降档位）。→ 系统不再降档，改为提示「已到当前最低档」并把反馈升级为**周度触点 T2 的输入**，由学习者裁决是否重定目标锚。

## 六、UC-06 喊停「停」（Safe Halt）

| 字段 | 内容 |
|---|---|
| **名称** | 喊停 |
| **ID** | UC-06 |
| **描述** | 学习者在任何时刻必须能立刻退出，且**不损失此前已落盘的进度**。碎片场景下「被打断」是常态而非异常——「随时中断、随时继续」（org-design §三）是四条不变量中 L-RESUME 的人机接口。 |
| **演员** | 学习者 |
| **组织受益** | 直接关联 **G0**：损失上界 = 一轮（≤30 秒量级）。若喊停有心理成本，学习者宁可硬撑到疲劳，G0 的损耗会转移到学习质量上 |
| **使用频率** | 中——碎片会话中被外界打断的概率高 |
| **触发原因** | 学习者发出 `停`——**系统可检测的关键词**；或 App 被系统杀死（等价触发，见 EX2） |
| **前提条件** | 存在进行中的会话（状态 = 进行中）。**若会话已结束，本用例不适用** |
| **后续条件** | ① 会话状态 = 已中断；② **当轮作废**（未落盘的当前轮不写入 journal）；③ **此前已落盘的全部轮次保留且可续**；④ 下一步指针**保持指向中断前最后一条落盘轮**，不推进；⑤ 若档位队列水位低于水位线，已登记后台补切 |

- **主要路径**（6 步）
  1. 学习者发出 `停`。
  2. 系统立即停止发新轮，并作废当前未完成的轮次。
  3. 系统确认此前已落盘的轮次完整保留。
  4. 系统把下一步指针保持为中断前最后一条落盘轮。
  5. 系统登记后台补切任务（若水位不足）。
  6. 系统结束会话，状态转为已中断；下次唤起从该指针继续。
- **替代路径**
  - **AC1**｜调用条件：`停` 发生在**一轮的边界**（刚微落盘完）。→ 当轮本就不作废，系统直接转收尾 → 步骤 4。
  - **AC2**｜调用条件：学习者在 B0 会话中说 `停`。→ 停止播放，按 **UC-03 的步骤 5** 记为退出条件命中，仍追加一行 `DD107 = 0` 的记录 → 步骤 4。**B0 的 0 轮不等于「什么都没发生」，仍需记账。**
  - **AC3**｜调用条件：会话尚未开练（已唤起未取到包）。→ 系统不建会话或作废空会话，不产生 journal 行 → 步骤 6。
- **异常情况**
  - **EX1**｜条件：作废当轮时该轮的作答已被系统读取但未落盘。→ 系统**丢弃该轮**并明确告知「本轮未计入」。理由：L-NOLOSS 只保护**已落盘**的内容，未落盘的轮次按可弃轮次处理（org-design §三）。
  - **EX2**｜条件：App 被强制杀死（未收到 `停`）。→ 系统以「最后一条落盘轮」为续学点，**损失上界 = 当前未完成的一轮**（**AC2 的用例落点：随机杀 ×10 全过**）。
  - **EX3**｜条件：下一步指针更新失败。→ 系统保留旧指针（保守：宁可少推进，不可错推进），并把失败计入待修复项，下次唤起优先重算派生。

## 七、UC-07 独立判读并回写判定（I-DISC 交接）

| 字段 | 内容 |
|---|---|
| **名称** | 独立判读并回写判定 |
| **ID** | UC-07 |
| **描述** | 学习者的作答被送到一个**没见过出题过程的上下文**中判定，并得到「判定 + 母语者式反馈」。出题者与判读者分离是死法 D4（自练自判固化错误语感）的**唯一**对策。 |
| **演员** | 学习者（被判定方）；判定由系统内的判读官角色执行 |
| **组织受益** | 直接关联 **SM1 / SM2 / G2 / G3**：判定可靠性是全部学习层指标的共同前提。**若 D4 发生，指标会漂亮而能力不涨**——指标本身即失去意义 |
| **使用频率** | 每个交互轮次一次（高频、后台化，学习者通常无感） |
| **触发原因** | 一条交互轮次落盘（DD101–DD111 写入完成）——**系统可检测的动作**，由落盘事件触发 |
| **前提条件** | ① 该轮已落盘；② 判定级别由 DT-1 选定（T0 / T1 / T2）；③ 判读请求载荷**不含**陪练官上下文 |
| **后续条件** | ① 判定结果与级别标记已落盘（DD204 / DD109）；② 置信度 <0.70 时状态为待复核而非采信；③ 错误条目已入错题本；④ **判读官推理过程不写入学习者会话上下文**；⑤ 判读请求的载荷边界可被日志审计（AC5） |

- **主要路径**（7 步）
  1. 教练官把作答内容与题目标识提交给判读官。
  2. 系统建立**全新上下文**，载荷仅含作答与题目，不含出题过程的任何痕迹。
  3. 判读官在独立上下文中给出判定（正确 / 不自然 / 错）。
  4. 系统按 DT-1 记录的级别打上级别标记并落盘。
  5. 判读官给出母语者式三栏反馈（你写的 / 母语者会写 / 差别一句话）。
  6. 系统把「不自然」与「错」两类条目写入错题本。
  7. 系统把判定结果用于掌握度升降判定与复现信号（**须满足难度锚门槛**）。
- **替代路径**
  - **AC1**｜调用条件：置信度 < 0.70。→ 判定状态转「待复核」并入补判队列 → **不阻断训练**；若联网且同步已同步，转入 AC2，否则保持待复核。
  - **AC2**｜调用条件：AC1 且网络与同步条件满足。→ 执行 T2 补判；补判结果**覆盖**原判而不累积；若补判置信仍 <0.70，最多重试 3 次后永久挂起并计入降级统计（决策树 §二）。
  - **AC3**｜调用条件：离线判定（T0/T1）。→ 系统按原判继续训练，同时把该判定计入**分层统计**用于发现判定质量塌陷（死法 A9）。
- **异常情况**
  - **EX1**｜条件：判读请求载荷中检测到陪练官上下文（出题提示、生成轨迹、候选答案）。→ 系统**中止本次判读**并记为工程缺陷，不落盘判定。**这是 AC5 的可测形式**：该分支被触发即判 AC5 不通过。
  - **EX2**｜条件：判读服务整体不可用。→ 该轮标为「待判」并继续训练；判定链在恢复后补齐，**不因判读失败阻塞学习**。
  - **EX3**｜条件：事后分层统计显示某级别判定质量塌陷。→ 该级别的判定**批量转待复核**，并按状态表 §二 复活路径④ 允许重练。**这条是 A9 的补救路径，不是可选项。**

## 八、UC-08 会话收尾记账与续学点落盘

|---|---|
| **名称** | 会话收尾记账与续学点落盘 |
| **ID** | UC-08 |
| **描述** | 会话结束时，把 journal 派生成人可读的账本视图，把「上次练到哪」写成一个可跨设备、跨进程重建的指针。学习者与开发者都能**读**它——账本不是数据库，是可审计的文本契约。 |
| **演员** | 学习者（受益方）；执行方为教练官 |
| **组织受益** | 关联 **G0 / L-REFORM**：`15-requirements-mapping-matrix` 所依据的「凭账本即可完全恢复运行」——**AC7 的产品级实测就是删除 App 重装后从账本完整恢复** |

- **主要路径**（7 步）
  1. 系统读取本次会话的全部落盘行。
  2. 系统重写 session-log 当前行为人读摘要。
  3. 系统把下一步指针设为最后一条落盘轮，并给出下一档建议。
  4. 系统回写该档位队列水位。
  5. 系统判定水位是否低于水位线，必要时登记后台补切任务。
  6. 系统把判定与复现信号回写给记忆官。
  7. 系统结束会话（状态 = 已完成 或 已中断）。
- **替代路径**
  - **AC1**｜调用条件：本次以 Safe Halt 结束。→ 下一步指针**保持**指向中断前最后落盘轮而非推进 → 回到步骤 4。（**UC-06 的 AC2 与本路径互为镜像**）
  - **AC2**｜调用条件：本次为 B0 会话。→ 指针**不推进**、不触发复现信号，仅追加输入量统计 → 回到步骤 5。（见 UC-03 §3.2）
  - **AC3**｜调用条件：本次会话的判定仍处「待复核」。→ 指针照常推进（判定不阻断训练），待复核判定在补判后**就地更新**并重算派生 → 回到步骤 2。
- **异常情况**
  - **EX1**｜条件：派生重写过程中 App 被杀。→ journal 是唯一事实源，**下次唤起重跑派生即可恢复**，指针以下一条落盘轮为准重建。**这就是 AC2 的容错机制本身。**
  - **EX2**｜条件：队列水位回写失败。→ 系统保留旧水位并登记待修复项；**水位只影响下次唤起取包，不影响本次已完成的记账**。
  - **EX3**｜条件：设备在同步失败状态下收尾。→ 系统照常完成单机记账（**功能不降级一分**），并如实标注「账本同步至 T，来源设备 X」。同步失败是独立第四态，不得归入「同步中」或「单机」（状态表 §八）。
