## 二、逐系统清单与失效降级

> **「集成失效后果」一栏是本图的核心**。单模运行时（app-design §二「同步失效不降级单机功能一分」），只有当每个集成的失效后果都可被写成一句「单机仍能做什么」，双模原则才算真正成立，而非口号。

### 组 2 · 外部 AI 服务

| 系统 | 方向 | 传什么 | 失效后果（单机仍能做什么） |
|---|---|---|---|
| 云 LLM provider | ⇄ | 角色提示词 + 练习项 + 学习者作答 → 判定/材料 | **T0 预嵌判定可用**；生成类任务（补切新材、输出练习）不可做；队列耗尽后无新材 |
| 本地模型（T1） | ⇄ | 同上 | T0 可用；开放作答的 T1 判定退化为受限 T0（关键词匹配），结果低置信 |
| 用户密钥 | → | BYOK 写入 / 读取 | 无密钥则云服务全不可用；**纯 T0 + 本地兜底包仍可无限期运行** |

### 组 3 · 平台能力（L4）

| 系统 | 方向 | 传什么 | 失效后果 |
|---|---|---|---|
| TTS 引擎 | → | 文本 → 音频（批量预生成） | 无音频则 B0 档不可用；B2/B5/B15 不受影响（文本练习） |
| ASR 引擎 | → | 语音 → 文本 | 影子跟读不可用（Phase 2 能力）；B0 改为纯听 |
| 账本文件 I/O | ⇄ | 六件账本读写 | **核心依赖，不可失效**。若失效则系统不成立——这是唯一一个无降级路径的集成 |
| Keychain | ⇄ | 凭据存取 | 密钥读不到则退 T0/本地 |
| Widget / 快捷指令 | → | 唤起意图 | **唤起成本上升**（从一次点击变为打开 App）。触点原则受损但功能不减——**这是 A4 推送诱惑的对偶**：不推推送，改推唤起 |
| 菜单栏 / 全局热键 | → | 唤起意图 | 同上 |
| 后台音频播放 | → | 播放控制 | B0 变前台播放，锁屏不可控 |

### 组 4 · 同步通道（⊘ 可选）

| 系统 | 方向 | 传什么 | 失效后果 |
|---|---|---|---|
| iCloud Drive | ⇄ | 账本目录整目录 | **单机功能完全不受影响**（双模原则兑现点）；跨设备能力丧失 |
| Syncthing / WebDAV | ⇄ | 同上（将来） | 同上 |
| Handoff | → | 会话接力信号 | 接力退化为「文件同步 + ≤1 分钟」路径（AC9 允许） |

### 组 5 · 开发/运维侧

| 系统 | 方向 | 传什么 | 失效后果 |
|---|---|---|---|
| 文本编辑器 | ⇄ | 直接读写账本 | 无 |
| Node CLI 壳 | ⇄ | 读同一账本跑 B2/B5 | 无 |
| git | → | 账本版本 | 无 |
| 补切任务脚本 | → | 写 corpus/ 与 queue/ | **队列断供**——但预切队列水位线 ≥2/档 的设计给了缓冲 |

## 四、本图暴露的三处集成问题

### 4.1 账本文件 I/O 是唯一无降级路径的集成

全部集成里，只有它失效会让系统不成立。其余每一个都能写成「单机仍能做什么」。**这一栏的空缺本身就是设计要求**：账本 I/O 的可靠性必须由 AC7（人工可读、删除重装可恢复）与 AC11（冲突注入零行丢失）保障，不能靠其他集成的降级路径兜底。

### 4.2 TTS 失效会孤立 B0 档

B0 档（纯听/影子跟读）完全依赖音频。若 TTS 不可用，**B0 整档报废**，而 B0 是四档中使用场景最广的一档（做饭/走路/通勤）。

**现有设计对此只有一句「本地引擎为基线」，没有失效路径**。⚠️ 已登记：需在批次 9（系统流程）补 TTS 失效的降级链——若无音频，B0 是否可退化为「无音频的复现题」？代价是它不再是「零交互」而是变成 B2。**这是一条尚未建模的业务决策**。

### 4.3 组 5 是被低估的集成方

`org-design` 与 `app-design` 反复强调「账本是产品本体」「CLI 壳读同一账本」，但**集成图从未把开发/运维侧画成一组**。它的意义在于：**它是 I-REFORM 唯一的实测路径**——组 5 能读写账本，就证明账本真的不依赖 App 存活；反之，账本只能经 App 读写，则「壳可替换」是空话。

**建议将组 5 保持为独立一组而非并入核心系统**，因为它的失效后果与生产路径完全不同：组 5 失效不影响用户使用，只影响可维护性。
